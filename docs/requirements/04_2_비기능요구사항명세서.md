# 비기능 요구사항 명세서: ThinQ Pregnancy Life Mode

- 작성 기반: `01_PRD.md`, `01_MVP.md`, `02_유스케이스다이어그램.md`, `03_유스케이스명세서.md`, `04_1_기능요구사항명세서.md`
- 비기능 ID 규칙: `NFR-XXX` (일련번호 3자리)
- 구분: 성능 / 보안 / 개인정보 / 안정성 / 사용성 / 접근성 / 준법·고지
- **번호 체계 원칙**: 구분별 번호가 연속되지 않는 구간(보안의 NFR-026 등)이 있으나 **재번호하지 않는다.** NFR ID는 백엔드 코드·설정 파일(`backend/app/services/routine/fallback.yaml`, `backend/README.md`)과 `docs/api.md` 등 다수 문서에서 참조하고 있어, 재번호 시 해당 참조가 조용히 어긋난다. 신규 항목은 기존 번호 뒤에 이어 붙인다.

## 1. 성능

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-001 | 성능 | AI 엔진의 하루 루틴 생성 응답은 사용자가 체감 가능한 시간 내에 완료되어야 한다. | API 응답시간 p50 ≤ 5초, p95 ≤ 10초 (부하테스트로 검증) |
| NFR-002 | 성능 | 주요 화면(컨디션 체크, 루틴 홈, 캘린더)은 빠르게 로딩되어야 한다. | 화면별 TTI(Time To Interactive) ≤ 2초 (4G/LTE 환경 기준) |
| NFR-003 | 성능 | 서비스는 동시 다발적 사용자 접속을 안정적으로 처리해야 한다. | 동시 접속 1,000명 부하테스트에서 오류율 < 1%, 평균 응답지연 ≤ 3초 |
| NFR-004 | 성능 | AI 챗봇 대화 응답은 실시간 대화로 인지될 수 있는 수준이어야 한다. | 챗봇 응답시간 p95 ≤ 8초 |

## 2. 보안

|---|---|---|---|

| NFR-006 | 보안 | 가전 제어 API 호출은 반드시 사용자 인증과 기기 소유권(가족 계정 권한) 검증을 거쳐야 한다. | 무권한 제어 시도 차단율 100% (침투테스트/모의해킹으로 검증) |
| NFR-007 | 보안 | 서버-클라이언트, 서버-외부 API(AI 엔진, ThinQ 가전, 홈카메라) 간 모든 통신은 암호화되어야 한다. | 전 구간 TLS 1.2 이상 적용, 평문 통신 구간 0건 |
| NFR-008 | 보안 | 저장 데이터 중 민감정보(건강 수치, 영상 파생 데이터)는 저장 시 암호화되어야 한다. | AES-256 이상 암호화 적용률 100% |
| NFR-009 | 보안 | AI 엔진 등 외부 API 연동 시 인증키/토큰은 안전하게 관리되어야 한다. | 시크릿 값 코드/저장소 노출 0건 (정적 분석 도구 검사) |
| NFR-026 | 보안 | 남편 초대는 **1회성 토큰**으로 발급되고 일정 시간 후 만료되어야 한다. 초대 알림이 ThinQ 서비스를 통해 전달되더라도 연동 승인은 이 토큰 검증을 거쳐야 하며, 만료·재사용 토큰으로는 연동될 수 없어야 한다. | 토큰 유효시간 ≤ 72시간, 만료·재사용 토큰 연동 차단율 100%, 중복 연동(이미 다른 아내 계정과 연동된 남편) 차단율 100% |

## 3. 개인정보

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-010 | 개인정보 | 임신·건강 정보(혈당, 체중, 통증 점수, 컨디션 기록 등)는 민감정보로 분류해 일반 데이터와 분리 관리되어야 한다. | 민감정보 필드 암호화·접근제어 적용률 100% |
| NFR-011 | 개인정보 | **홈카메라 원본 영상은 저장하지 않는다.** 움직임 패턴만 인식해 활동 로그 등 파생 데이터만 유지해야 한다. | 원본 영상 저장 0건(프레임·landmark 좌표 등 영상 복원 가능 데이터 포함), 파생 로그만 보관 |
| NFR-012 | 개인정보 | 사용자는 홈카메라 기반 모션 모니터링 **동의를 언제든 철회**할 수 있어야 하며, 철회 시 즉시 데이터 수집이 중단되어야 한다. **감지 ON/OFF 토글과는 동작이 다르다** — ON/OFF는 데이터 수집 여부만 제어하므로 OFF 시 신규 감지만 중단되고 기존에 저장된 당일·과거 기록은 삭제되지 않고 계속 조회 가능해야 한다. | 동의 철회 요청 후 데이터 수집 중단까지 소요시간 ≤ 1분. OFF 전환 시 기존 기록 삭제 0건 |
| NFR-013 | 개인정보 | 남편 계정과 공유되는 데이터 범위는 **서비스가 정의한 공유 범위(오전 컨디션 리포트, Daily 리포트, 가사 요청, 홈캠 공유 정보, 캘린더 기록)로 제한**되어야 하며, 그 밖의 아내 데이터(프로필 원본, 컨디션 원본 입력값, AI 대화 이력)는 남편 화면에 노출되지 않아야 한다. | QA 체크리스트 기준 공유 범위 외 항목 노출 0건 |
| NFR-014 | 개인정보 | AI 엔진(외부 API)에 전달되는 사용자 데이터는 서비스 목적(루틴 생성)에 필요한 최소 항목으로 제한되어야 한다. | 외부 전송 데이터 항목 대비 실제 사용 항목 비율 100% (불필요 항목 전송 0건) |
| NFR-027 | 개인정보 | AI 챗봇 대화 이력(conversation history)은 **이후 루틴 추천의 개인화 목적으로만 재사용**되어야 하며, 보관 기간과 파기 기준을 사전에 정의해야 한다. 대화 원문은 Daily 리포트에 저장하지 않고, 루틴이 실제로 변경된 결과(routine event)만 리포트에 반영한다. | 대화 이력의 목적 외 사용 0건, 보관 기간 정책 문서화 100%, Daily 리포트 내 대화 원문 저장 0건 (FUC-W-CHAT-004 연계) |

## 4. 안정성

| 비기능 ID | 구분 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-015 | 안정성 | 서비스는 안정적으로 상시 이용 가능해야 한다. | 월간 서비스 가용성(Uptime) ≥ 99.5% (월 다운타임 ≤ 3.6시간) |
| NFR-016 | 안정성 | AI 엔진 응답 실패 시에도 사용자에게 빈 화면이 노출되지 않아야 한다(FUC-W-CALLBACK-001 폴백 연계). | 폴백 로직 작동 성공률 ≥ 99.9%, 빈 화면 노출률 < 0.1% |
| NFR-017 | 안정성 | 외부 시스템(ThinQ 가전, 홈카메라) 장애가 발생해도 나머지 핵심 기능은 정상 동작해야 한다. | 장애 격리 테스트에서 타 기능 정상 동작률 100% |
| NFR-018 | 안정성 | 사용자 데이터(프로필, 컨디션, 루틴 기록)는 주기적으로 백업되어야 한다. | 일 1회 이상 자동 백업 성공률 100%, 분기 1회 이상 복구 테스트 수행 |
| NFR-028 | 안정성 | **Daily 리포트는 날짜당 1개만 존재해야 한다.** 동일 날짜에 완료된 여러 루틴은 하나의 Daily 리포트에 누적 저장되어야 하며, 중복 생성이나 데이터 누락이 발생하지 않아야 한다. | 동일 날짜 Daily 리포트 중복 생성 0건, 같은 날 복수 루틴 생성 시나리오에서 루틴·Routine Event 누락 0건 (FUC-W-COND-004·FUC-W-REPORT-001 연계) |

## 7. 준법 · 고지
