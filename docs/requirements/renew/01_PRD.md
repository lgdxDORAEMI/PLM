## 1. 배경 및 문제 정의

### 1.1 비즈니스 문제
- 스마트홈/IoT 업종 전체 MAU는 성장세이나, ThinQ 신규 설치 수는 전월 대비 30% 감소
- ThinQ 사용자의 70%는 타 앱(SmartThings 등)을 병행 사용 중이며, ThinQ 이탈자의 최종 목적지는 SmartThings
- 이탈률·락인율 모두 SmartThings 대비 비대칭적으로 불리한 구조 (ThinQ 단독 사용자 락인 29.8% vs SmartThings 65.8%)
- **결론**: 단순 기능 추가가 아니라, 사용자가 ThinQ를 적극적으로 쓰기 시작할 명확한 '생활 변화의 계기'가 필요

### 1.2 기회 지점 — 생애전환기(Life Transition)
- 생애전환기(결혼, 부모됨, 이사, 은퇴 등)에는 소비자가 자발적으로 브랜드 선호를 바꾸는 비율이 유의미하게 높음 (Andreasen, 1984)
- 생애사건 발생 시 소비 동기와 방식이 변화함 (Yap & Kapitan, 2017)
- 임신은 구매를 넘어 생활방식 자체가 지속적으로 변화하는 대표적 Life Event

### 1.3 임신으로 달라지는 생활 조건
1. **생활 관리 기준 변화**: 태아 건강 기준으로 식품·제품·생활환경 재판단 필요
2. **생활 행동 조정**: 정보 탐색과 대체 제품 구매, 시간·비용 부담 및 효과 불확실성 발생
3. **신체적 수행 조건 변화**: 임산부 요추/골반통 유병률 63% (Shanshan et al., 2024, 38개 연구·21,533명 메타분석) → 기존 생활방식 수행 자체가 어려워짐

### 1.4 출산 이후로 이어지는 변화
- 임신 중 시작된 생활 변화는 출산으로 끝나지 않고 지속됨
- 산모의 신체 회복과 신생아 돌봄이 동시에 같은 공간(가정)에서 발생
- 변화 범위가 임산부 개인 → 가족 역할·가정 생활방식으로 확대 (보건복지부, 2025 「산후조리 실태조사」)

### 1.5 기존 서비스의 공백
검토 대상: 정부 「맘편한 임신 원스톱 서비스」, 삼성 SmartThings 「패밀리 케어」, LG전자 기존 개별 가전 케어 기능(공기청정기 싱글청정모드 등)
→ **임신부터 산후 초기까지 달라지는 생활조건에 맞춰 가정 내 생활행동과 가전 사용을 연결하는 지원은 주요 서비스에서 뚜렷하게 확인되지 않음**

### 1.6 가설
> 임신·출산 전환가구는 달라진 생활조건에 맞는 생활관리 방법을 판단하고 실행하는 데 어려움을 겪을 것이다.

## 2. 리서치 방법 및 데이터 근거

### 2.1 데이터 수집
- **온라인 커뮤니티**: 네이버 카페 + 커뮤니티 앱 5개 소스(레몬테라스, 맘이베베, 맘스홀릭 베이비, 임산부 모여라, 미즈넷), 총 226,022건 수집 → 전처리 후 86,821건 (수집 기간 2023.01.01~2026.09.06)
- **네이버 블로그**: 6,003건 수집, 필수/포함/제외 키워드 필터링 후 912건 (전체 232,025건 수집 중 정제 후 83,874건 사용)
  - 필수 키워드: "임신"
  - 포함 키워드: 살림/집안일/외출/수면/식사
  - 제외 키워드: 협찬/제공받아/지원받아/소정의/원고료 (광고성 제외)

### 2.2 분석 파이프라인
1. 데이터 수집 (블로그·지식인·카페·커뮤니티 앱 크롤링)
2. LLM 기반 데이터 분류 (생활맥락 글 선별, 광고/체험후기 제거) → 87,733건
3. 데이터 전처리 (품사 태깅, URL/이메일/전화번호 제거, 특수문자 제거, 불용어 제거, 100자 미만 제거) → 83,874건
4. 임베딩 벡터 변환 (SVD·Doc2Vec·SBERT 3종 비교)
5. 클러스터링 (K-means vs HDBSCAN 비교 — 실루엣 계수 0.043 vs 0.129로 HDBSCAN 채택), UMAP + HDBSCAN으로 28개 클러스터 도출 → TF-IDF 키워드 분석 및 원문 검토로 노이즈 클러스터 9개 제외 → 4개 상위 군집으로 축약

### 2.3 Actor 정의
| Actor | 페르소나 | 유형 | Desire | Pain Point |
|---|---|---|---|---|
| Actor 1 | 최유나, 30세 | 신체 변화 적응형(생활 관리형) | 달라진 몸 상태에 맞는 생활 방식을 찾아 불편·걱정을 줄이고 싶음 | 증상마다 대처법이 달라 무엇을 어떻게 조절해야 안전한지 판단하기 어려움 |
| Actor 2 | 박서연, 31세 | 태아 상태 확인형 | 아기 상태 신호가 정상인지 빠르게 확인하고 안심하고 싶음 | 아기 상태를 직접 확인 못하고 간접 신호만으로 위험 여부 판단해야 함 |
| Actor 3 | 이수진, 32세 | 출산 준비/구매 계획형 | 출산에 필요한 것을 미리 파악하고 준비하고 싶음 | 용품·분만방식·입원준비를 한꺼번에 결정해야 하는데 정보/추천이 제각각 |
| Actor 4 | 김지윤, 33세 | 신생아 돌봄 탐색형 | 아기에게 맞는 돌봄 방법을 쉽게 선택하고 반복되는 관리 부담을 줄이고 싶음 | 제품/관리법마다 정보가 달라 신생아에게 안전한 선택인지 판단 어려움 |

### 2.4 우선순위 결정 — 기회영역 분석
- 중요도-만족도 매트릭스 기준, **Actor 1의 Action 1·2**가 중요도 가장 높은 underserved 영역
- **Action 4·5**는 만족도가 평균 이하이면서 중요도도 높은 구간 → 포괄적 문제 파악을 위해 함께 포함
- → **본 서비스는 Actor 1(신체 변화 적응형)의 Action 1(입덧/식사 조절), Action 2(통증/자세 조절), Action 4(혈당·체중 관리), Action 5(수면 조절)를 핵심 문제 영역으로 설정**

### 2.5 CAM 분석 핵심 인사이트 (Actor 1)
- **Action 1 (입덧·식사)**: 임신 중 식사는 정해진 식단이 아니라 그날의 입덧·식욕·소화 상태에 따라 계속 조정해야 하는 행동. 고정된 음식 추천보다 현재 컨디션에 맞는 대체 판단 지원이 필요
- **Action 2 (통증·자세)**: 신체 변화는 통증에서 끝나지 않고 기존 생활 동작 자체를 바꿈. 통증 치료보다 현재 몸 상태에 맞게 일상 행동을 수행하도록 자세·환경을 보조하는 지원 필요
- **Action 5 (수면)**: 신체 변화와 생활 패턴 변화가 복합적으로 작용해 기존 수면 방식이 맞지 않게 됨. 단순 수면시간 관리보다 몸 상태·자세·야간 각성 패턴을 함께 반영한 환경적 지원 필요
- **Action 4 (혈당·체중)**: 식단·측정·운동을 매일 반복해야 하며 관리 행동이 많고, 같은 행동에도 결과가 예상과 다르게 나타나 일상 일정과 병행이 어려움

### 2.6 대표 페르소나
**한서현, 30세, 사무직 직장인(출산 전까지 근무), 첫째 임신 28주**
- 입덧 극심기는 지났지만 울렁거림·소화 부진 지속, 통증 점수 8/10, 임당 검사 경계 판정·공복혈당 높음, 임신 전 대비 +8kg, 새벽 2~3회 기상
- Pain: "몸 상태가 매일 달라지니까 계속 적응하기 힘들어요"
- Goal: "매일 달라지는 몸 상태에 맞춰 먹고, 움직이고, 쉬고, 관리하는 방식을 어렵지 않게 조절하고 싶어요"

### 2.7 4D-CX 가치 설계
| 축 | 기능 방향 | 사용자 감정가치 |
|---|---|---|
| 정신적 (Actor-Data) | 프로필 연동 자동 추천 기준, 당일 상태 기반 메뉴 추천, 컨디션 기반 활동 루틴, 피드백 반영 재조정 | 판단 안 해도 맞춰진다는 편리함, 지속적 신뢰감 |
| 물리적 (Actor-Artifacts) | 냉장고 재료 기반 즉시조리 추천, 저부담 루틴 가이드, 수면환경 자동설정, 위험수치 감지 알림 | 즉각적 실행감, 안도감 |
| 문화적 (Actor-Actor) | 컨디션 가족 공유, 선택적 루틴 공유, 역할 분담 | 관계 편안함, 가족 협력감 |
| 시스템적 (Artifacts-Artifacts) | 프로필→가전 실행 연결, 컨디션 기록 누적, AI 루틴 생성, Daily Report 반영 | 실행 편의성, 개인화 축적감 |

## 3. 서비스 개요

- **서비스명**: ThinQ Pregnancy Life Mode
- **서비스 목적**: 임산부의 임신 주수, 당일 컨디션, 오늘 해야 할 일, 과거 생활 기록을 바탕으로 식사·가사·건강·수면 루틴을 개인화하고, 가전 실행과 가족 분담까지 연결하는 AI 생활관리 서비스
- **고객 감동 목표**: "ThinQ가 임신 기간 전체를 함께하는 생활관리 파트너가 되어, 임산부의 매일 달라지는 생활 부담을 줄인다."

### 3.1 핵심 액터

서비스는 내부 액터(사용자) 2종과 외부 액터(연동 시스템) 3종, 총 5개 액터로 구성된다.

#### 내부 액터 (서비스 사용자)
| 구분 | 역할 |
|---|---|
| 아내 (Primary User) | 임신 관련 정보·컨디션 입력, 개인화 루틴 생성·수정·실행 |
| 남편 (Partner User) | 아내가 공유한 정보 확인, 집안일·식사·가전 실행 등 케어 행동 분담 |

#### 외부 액터 (연동 시스템)
| 구분 | 역할 |
|---|---|
| **AI 엔진** | 프로필·컨디션·임신 주차·전일 활동 데이터를 입력받아 식사/가사/건강/수면 루틴 생성, 메뉴 재추천, 챗봇 응답 등 **서비스 내 모든 개인화 판단을 수행하는 핵심 의사결정 주체**. LLM 기반 외부 API 또는 별도 백엔드 추천 엔진으로 연동되는 시스템 컴포넌트 |
| ThinQ 연동 가전 | 로봇청소기, 세탁기·건조기, 식기세척기, 공기청정기, 냉난방기 등 AI 엔진이 결정한 실행 명령을 받아 실제로 동작하는 외부 스마트홈 디바이스 시스템 |
| 홈카메라 시스템 | 자세·활동 패턴을 감지해 모션 데이터를 AI 엔진에 제공하는 외부 센서 시스템 (의료 진단 기능 아님, MVP 범위 제외·Phase 2) |

> **설계 원칙**: 이 서비스에서 "무엇을 추천할지·어떻게 조정할지"에 대한 판단은 전적으로 AI 엔진이 담당한다. 아내/남편용 화면과 로직은 AI 엔진의 판단 결과를 입력받아 사용자에게 보여주고, 사용자 행동(입력·완료체크·요청)을 다시 AI 엔진에 데이터로 전달하는 역할에 집중한다. 즉 F4(AI 하루 루틴 생성), F5(식사 가이드), F7(건강 가이드), F8(수면 가이드), F9(AI 챗봇)는 모두 AI 엔진 호출을 전제로 한다.

## 4. 기능 요구사항

### 4.1 아내용 기능

**F1. 임산부 프로필 설정**
- 입력 항목: 출산 예정일, 나이, 임신 전 키/몸무게, 초산/경산, 단태아/다태아, **알레르기**, **병원에서 주의받은 진단 및 그 외 들은 말(자유 입력)**
- **출산예정일을 모르는 경우 마지막 생리 시작일(LMP)을 대신 입력**받아 LMP+280일로 출산예정일을 자동 산출한다. 둘 중 하나만 입력해도 다음 단계로 진행 가능
- **알레르기**: 갑각류·견과류·우유·계란·밀 등을 다중 선택하며, 선택한 재료는 식사 가이드(F5) 메뉴 추천에서 제외된다. "없어요" 선택 시 나머지 선택은 해제된다
- **주의 진단 및 자유 입력**: 임신성 당뇨 경계·빈혈·고혈압·조기진통·역류성 식도염 등을 다중 선택하고, 진료에서 구두로 들은 안내 내용을 자유 텍스트("그 외 들은 말")로 입력한다. 두 값은 혈당·혈압 기준의 메뉴 조정과 활동 강도 조정 기준으로 사용된다
- 알레르기와 주의 진단은 선택 사항이며 미입력 상태로 저장한 뒤 이후 프로필 수정에서 추가할 수 있다
- 입력값은 임신 주수 계산 및 이후 모든 개인화 추천의 기본 데이터로 사용
- **최초 등록(1회성)과 이후 수정은 구분된다.** 최초 등록은 빈 화면에서 전체 항목을 입력하며, 완료 직후에만 F1-1(남편 초대하기)로 자동 연결된다. 이후 수정은 저장된 값이 채워진 화면(F1과 같은 화면 재사용)에서 원하는 항목만 선택해 바꾸고, 저장 후 바로 이전 화면으로 복귀한다.
- **전역 프로필 버튼**: 모든 화면 우측 상단에 프로필 버튼(≡)이 상시 노출된다. 클릭하면 F1과는 별개인 메뉴 화면(이름·임신주수·출산예정일 요약 표시)으로 이동하며, 여기서 '프로필 수정'/'남편 초대'(남편 미연동 시에만 노출)/'설정' 중 선택한다. '프로필 수정'은 저장된 값을 채운 F1 화면을 재사용한다. '설정'은 현재 플레이스홀더(상세 항목 미정)다.

**F1-1. 남편 초대하기**
- 진입 경로 2가지: ① 임산부 프로필 최초 등록 완료 직후 자동 노출(온보딩) ② 전역 프로필 버튼 메뉴의 '남편 초대' 선택(남편 미연동 상태에서만 메뉴 노출)
- 화면 구성: 연결 시 가능한 것 안내(오늘 컨디션 요약 받기, 집안일·식사 요청 받기, 하루 리포트 함께 보기), '초대장 보내기'/'나중에' 버튼
- '초대장 보내기' 클릭 시 시스템이 1회성 초대 토큰을 생성해 **남편의 ThinQ 앱으로 초대 알림 발송을 요청**한다. 이 알림은 **ThinQ 서비스 내 알림**이며 PLM 알림함(F14)과 무관하다. '나중에' 선택 시 초대를 건너뛰고 진입 경로에 따라 홈 화면(자동 진입 시) 또는 이전 화면(수동 진입 시)으로 이동
- **'나중에'를 선택해도 초대 기회가 사라지지 않는다.** 남편이 연동되기 전까지 전역 프로필 버튼 메뉴에 '남편 초대' 항목이 계속 남아 언제든 재시도 가능. 남편 연동이 완료되면 이 메뉴 항목은 자동으로 사라진다.
- 남편이 ThinQ 앱에 도착한 초대 알림을 선택하면 아내 계정과 연동됨(F1-1-H, 남편용 기능 참조)

**F2. 오늘의 컨디션 체크**
- 입력 항목 4종: **입덧**(5단계), **신체 통증**(허리·골반·다리·손목 **4부위** 각 5단계), **피로감**(5단계), **기분**(5단계)
- 부위별 통증 값은 건강 가이드(F7)의 콘텐츠 우선순위에, 피로감은 활동 강도와 수면 가이드(F8) 판단에, 기분은 가이드 문구 톤 조정에 반영된다
- 일별 데이터로 저장, AI 루틴 생성에 반영
- **루틴 생성 이후에도 수정할 수 있다.** 수정이 저장되면 변경된 정보를 반영해 오늘의 루틴을 다시 생성하고, 식사·가사·건강·수면 4종 생활 가이드도 새 루틴에 맞춰 함께 업데이트하며, 남편에게 "아내의 루틴이 변경되었습니다." **루틴 변경 알림**을 전송한다(F14). '저장하고 마치기'로 확정된 루틴은 갱신 대상이 아니며, 확정 이후의 재체크는 새 루틴 생성으로 처리한다(F11)

**F3. 오늘의 예정 활동 선택**
- 오늘 예정된 가사 관련 활동을 카드 형태로 복수 선택
- **컨디션 체크(F2)를 완료하면 이어서 진입하는 순차 단계**다. `오늘의 컨디션 체크 → 오늘의 집안일 선택 → AI 하루 루틴 생성 → 홈 복귀` 순서로 동작하며, 아무것도 선택하지 않아도 컨디션만으로 루틴 생성이 가능하지만 화면 자체를 건너뛰지는 않는다
- 목록에 없는 집안일은 직접 입력으로 추가할 수 있고, 추가한 항목도 목록 선택값과 동일하게 루틴 생성 요청에 포함된다
- AI가 실제 일정과 몸 상태를 함께 고려해 가사 루틴 조정 (예: "빨래" 선택 시 "앉아서 빨래 개기" 등 무리 없는 행동으로 변환 제안)
- **루틴 생성 이후에도 이 화면에 다시 진입해 수정할 수 있다.** 항목 추가·해제나 직접 입력 항목 수정이 가능하며, 저장 시 처리(루틴 재생성 → 4종 가이드 업데이트 → 남편에게 루틴 변경 알림)는 F2의 수정 규칙과 동일하다

**F4. AI 하루 루틴 생성**
- 홈 화면은 하나이며, 상단에는 인사말·임신 주차·이번 주차 맞춤 팁이 항상 고정 노출됨(프로필 등록 완료 이후부터 해당)
- 오늘 컨디션을 아직 입력하지 않은 경우: '오늘의 컨디션 체크하러 가기' CTA 버튼만 노출(하단 가이드 없음)
- 오늘 컨디션 입력을 완료한 경우: CTA 버튼은 사라지고, 스크롤 시 하단에 식사/가사/건강/수면 4개 가이드가 이어져 표시됨
- 입력 3축: ① 당일 컨디션(F2) ② 현재 임신 주차 ③ 전일 누적 모션 리포트 + **오늘의 예정 활동 선택 단계(F3)에서 입력받은 제약 조건**
  - ③의 예정 활동은 별도 화면을 거치는 명시적 단계이며, 컨디션 체크 직후 이 단계를 지나야 루틴 생성이 호출된다
- 조정 방식: 식사 가이드는 챗봇 대화로 조정, 나머지 3개는 설정창에서 직접 제어

**F5. 식사 가이드**
- 임신 주차별 부족 영양소, 당일 입덧/소화 상태, 혈당·임신성 당뇨 등 주의 진단, 프로필 등록 알레르기를 종합해 메뉴 제안
- 일반론이 아닌 "오늘 몸 상태에서 먹을 수 있는 것"으로 좁혀서 제안하는 것이 핵심
- 챗봇에게 컨텍스트("어제 이거 먹어서 오늘은 다른 걸로")를 전달하면 반영해 재추천
- 추천 수락 여부를 기록해 이후 추천에 반영
- 하위 기능: 추천 메뉴+이유, 영양 목적 표시, AI 상담 재추천, 남편에게 메뉴 카드 공유

**F6. 가사 가이드 & 가족 분담**
- 오늘 컨디션 + 예정 활동을 바탕으로 집안일을 3가지로 분류해 제안
  - 직접 수행: 현재 상태에서 부담 적은 집안일
  - 가전 수행: 로봇청소기, 세탁기·건조기, 식기세척기 등 ThinQ 연결 가전으로 대체
  - 가족 분담: 장보기, 빨래 이동, 무거운 물건 옮기기 등 부담 큰 집안일
- "카드 보내기" → 하단 선택창에서 남편에게 부탁할 가사를 선택해 전송

**F6-1. 실시간 탭 — 위험 행동 로그 (홈카메라 기반)**
- 홈카메라로 일상 행동·자세 패턴을 상시 감지하되, **설정된 임계값을 초과해 위험 행동으로 분류된 상황만** 로그로 남긴다(정상 범위 활동은 기록하지 않음)
- 감지 대표 예: 장시간 서 있기, 반복 숙이기, 물건 들기, 휴식 부족
- **실시간 화면의 조회 범위는 '오늘 발생한 감지 내용'으로만 한정된다.** 조회 범위를 오늘로 제한할 뿐이며 **데이터 자체를 삭제하거나 초기화하지 않는다**
  - 최근·전체·과거 날짜 선택 등 기간 필터는 실시간 화면에 제공하지 않는다
  - 오늘 이전의 감지 내용은 `캘린더 → 날짜 선택 → 해당 날짜 Daily Report → 홈캠 관련 주의사항` 경로로 조회한다
- **감지 ON/OFF는 데이터 수집 여부만 제어한다.** OFF로 전환하면 신규 감지만 중단되고, 이미 저장된 당일 기록과 과거 기록은 그대로 유지되어 계속 조회할 수 있다(기존 데이터 삭제 없음)
- **감지 기록은 단순 누적 기록이며, 다음 기능은 제공하지 않는다** — 기록 삭제, 확인 처리, 읽음/미읽음 처리, 개별 상태 변경. 감지된 기록은 오늘 화면에 시간순으로 누적 표시만 된다
- **진입 경로**: 다른 화면의 하위 메뉴가 아니라 **하단 메뉴바의 독립 탭('실시간')**으로만 진입 가능
- **아내와 남편이 동일한 로그를 공유 조회**한다 (남편도 자신의 ThinQ 앱 하단 메뉴바에서 같은 실시간 탭에 접근)
- **중요 제약**: 의료적 위험 진단 기능이 아니라 신체 부담 가능 행동 패턴 파악 용도로 한정
- 데이터 흐름: 위험 행동 판단 시 당일 로그 저장 → 실시간 탭에서 조회 → 다음 날 AI 루틴 생성에 반영(당일 즉시 루틴 변경 없음)

**F7. 건강 가이드**
- 당일 컨디션·임신 주차 기준으로 산책/체조 제안, 스트레칭 영상·마사지 방법·자세 교정 안내, 약/보충제 리마인더
- 설계 원칙: 부위 전체를 나열하지 않고, 전일 모션 모니터링 리포트 기반으로 부하가 많이 간 부위를 판단해 해당 콘텐츠를 우선 노출. 다른 부위 콘텐츠는 화면 하단에서 선택 조회 가능
- 하위 기능: 스트레칭 추천, 가벼운 산책/활동 제안, 부위별 스트레칭 영상, 활동 카드 완료 체크

**F8. 수면 가이드**
- **오전 컨디션 체크의 '피로감'**과 당일 통증, 임신 주차를 기반으로 수면 환경 조정
- **별도의 수면 기록을 수집하는 기능은 없다.** 근거 배너에 "어젯밤 수면 기록"을 쓰지 않으며, 수면 상태는 피로감 입력값을 기준으로 판단한다. 수면 가이드와 수면 상태 관련 안내도 모두 피로감 입력값을 반영해 제공한다
- 하위 기능: 수면 루틴 제안, 온도·조명·공기환경 설정, 연결 가전 실행, 수면 자세 추천(모션 모니터링 기반 그날 많이 쓴 관절 + 임신 주차 근거)

**F9. AI 챗봇**
- 자연어 입력("오늘 허리가 더 아파요", "저녁은 매운 음식이 먹고 싶어요", "오늘 빨래는 못 할 것 같아요")으로 기존 루틴의 관련 항목을 재조정
- 루틴 진행 상황과 무관하게 언제든 질의 가능, 현재 임신 주차·프로필 정보를 알고 있는 상태로 응답 (재설명 불필요)
- **진입 경로와 context 유지**: 챗봇 진입 경로는 두 가지다 — ① 홈 화면 하단 메뉴바의 '챗봇' 탭 ② 식사 가이드 내부의 추천 메뉴 카드(AI 재조정 바). 같은 챗봇 화면을 사용하더라도 **어디에서 진입했는지의 context를 전달·유지**한다. 예를 들어 식사 가이드에서 진입한 경우 "어떤 끼니를 다시 고르는 중인지"를 화면 상단 배너로 표시하고, 해당 맥락을 대화 시작값으로 AI 엔진에 함께 전달한다
- **대화 데이터 처리**: 챗봇에서 발생한 모든 대화가 Daily Report에 반영되는 것은 아니며, 두 종류의 데이터를 분리해 관리한다
  - **conversation history(대화 이력)**: 음식 관련 질문, 생활 관련 간단한 질문, 단순 정보 요청 등 일반 대화. 대화 내용을 DB에 저장하되 **현재 Daily Report에는 직접 반영하지 않는다**. 축적된 이력은 이후 루틴 추천의 개인화 정보로만 활용한다
  - **routine event(루틴 변경 결과)**: 사용자의 발화로 실제 루틴이 변경된 경우, 변경된 루틴 결과를 현재 루틴에 저장하고 Daily Report에 반영한다
  - 즉 **대화 원문 자체를 Daily Report에 저장하지 않으며**, 대화로 인해 루틴이 실제로 변경된 경우 그 변경 결과만 저장한다

**F10. 루틴 실행 및 완료 기록**
- 직접 행동(식사/스트레칭/산책 등): 카드에서 완료 체크
- 가전 행동: 연결 가전 실행 기록 기반 완료 상태 자동 반영
- 남편 요청: 요청 → 확인 → 완료 상태로 관리
- 위 데이터가 하루 기록으로 누적

**F11. Daily 리포트 & 컨디션 캘린더**
- **리포트 생성과 루틴 확정은 2단계로 분리된다.**
  1. **"오늘의 일정 마치기"**(홈 화면): 클릭 시 Daily 리포트를 생성해 화면에 표시한다. 이 단계에서는 아직 루틴이 확정되지 않는다
  2. **"저장하고 마치기"**(Daily 리포트 화면): 사용자가 이 버튼을 눌러야 **해당 루틴이 확정 상태가 되고**, Daily 리포트가 업데이트되며, 남편에게 Daily 리포트가 전달된다
- **금지 사항**: 하루가 끝났다고 해서 Daily 리포트가 자동 확정되지 않는다. **자정 기준 자동 Daily 리포트 생성, 루틴 종료 전 자동 확정은 만들지 않는다.** 루틴 종료 트리거는 사용자의 '저장하고 마치기' 뿐이다
- **저장하고 마치기 이후**: 확정된 루틴에는 새로운 행동을 이어 붙이지 않는다. 같은 날 다시 루틴을 시작하려면 오늘의 컨디션 체크를 다시 진행해 새 루틴을 생성한다
- **날짜 기준 Daily 리포트는 1개다.** 같은 날짜에 여러 개의 루틴이 생성·확정되더라도 리포트를 각각 만들지 않고 **하나의 Daily 리포트로 통합**한다. 데이터 구조는 `날짜 → Daily Report 1개 → 해당 날짜에 생성된 여러 Routine 및 Routine Event 누적` 형태로 처리한다
- 리포트 포함 내용: 오늘 실행 루틴 목록, 가전 작동 이력, 시청한 건강 영상, **홈캠 관련 주의사항**
  - 홈캠 정보는 감지된 raw data를 그대로 노출하지 않고 **주의사항 문구 수준으로만 제공**한다 (예: "허리 부담이 발생할 수 있는 행동이 확인됨", "장시간 서 있는 행동이 확인됨", "반복적인 숙이기 행동이 있었음", "휴식이 필요할 수 있음")
  - **정확한 감지 기준값·횟수·시간 기준·수치 계산 방식은 현재 확정하지 않으며, 추후 백엔드 및 감지 로직 개발 과정에서 정의한다.** 따라서 관절 부담 초과 횟수·최다 부담 관절 같은 수치 집계 형태의 요약은 기준 확정 이후에 반영한다
- 날짜별 누적 항목: 컨디션 기록, 추천 루틴, 실제 실행 여부, 가전 실행 내역, 가족 분담 내역
- 컨디션 캘린더에서 날짜별 컨디션·리포트 조회, 오늘 입력한 컨디션은 자동 기록되어 다음 날 화면·추천에 반영

**아내용 전체 흐름**
```
프로필 설정 → 아침 컨디션 체크 → 오늘 예정 활동 선택 → AI 루틴 생성
→ 오전 레포트 자동 공유 → 식사·가사·건강·수면 가이드 실행
→ (필요 시) 남편에게 가사 요청 → 각 루틴 완료 기록
→ 오늘의 일정 마치기 → Daily 리포트 확인 → 저장하고 마치기(루틴 확정 + 남편 전송)
→ 캘린더 저장
```

### 4.2 남편용 기능

**F1-1-H. 초대 수락 및 계정 연동**
- 아내가 초대를 발송하면 **남편의 ThinQ 앱에 초대 알림이 도착**한다. 남편이 알림을 선택하면 초대 토큰 검증 후 아내 계정과 연동되고, 남편용 홈 화면인 **캘린더 화면**으로 이동한다
- 초대 알림은 **ThinQ 서비스 내 알림**이며 PLM 알림함(F14)과 무관하다
- 연동 완료 후 오전 컨디션 레포트, 가사 요청, 실시간 탭 등 공유 기능을 사용할 수 있는 상태가 됨

**F12. 오전 컨디션 레포트 확인**
- 포함 내용: 현재 임신 주수, 오늘 아내 컨디션, 오늘 예정 활동, AI 생성 4대 가이드 요약
- **전송 트리거**: 아내의 아침 컨디션 체크 완료로 시작되는 일련의 흐름 중 **AI 하루 루틴 생성이 완료된 직후** 자동 생성·공유된다. 리포트에 4대 가이드 요약이 포함되므로 루틴이 생성되기 전에는 리포트를 구성할 수 없기 때문이며, 흐름 순서는 `컨디션 체크 완료 → 오전 컨디션 저장 → 예정 활동 선택 → 루틴 생성 → 남편에게 오전 리포트 전송`이다
- **AI 루틴 생성이 실패한 경우**: 폴백 루틴(전일 루틴 또는 기본 템플릿)이 제공되면 그 내용을 기준으로 리포트를 생성·전송하고, 폴백까지 실패해 표시할 루틴이 없으면 **전송을 보류**했다가 재시도로 루틴이 생성된 시점에 전송한다
- 오전 리포트 전송 조건과 Daily 리포트(F11) 전송 조건은 서로 다르며, 두 조건을 분리해 구현해야 한다 — 오전 리포트는 루틴 생성 완료 시점, Daily 리포트는 '저장하고 마치기' 시점
- 남편은 아내가 하루 루틴 전체를 마치지 않았더라도 오전 리포트를 확인할 수 있다

**F13. 캘린더 (메인 화면)**
- 날짜 선택 시: 오전 컨디션 레포트, 해당 날짜 주요 컨디션, 추천 루틴 요약, 루틴 수행 결과, 가족 분담 기록 확인
- 아내의 임신 기간 생활 기록을 날짜별로 확인하는 리포트 허브 역할

**F14. 상단 알림 벨**
- 알림 종류는 **3종뿐이다** — ① 오전 컨디션 레포트 도착 ② 가사 요청 도착 ③ **루틴 변경**("아내의 루틴이 변경되었습니다.")
- **모든 상태 변화가 알림을 발생시키지는 않는다.** 가사 요청의 미확인·확인·미완료 등 상태 변화에 대해서는 별도 알림을 생성하지 않으며, 해당 상태는 요청 화면에서 조회한다. 루틴 변경 알림은 이와 별개로 **아내가 컨디션 또는 예정 활동을 수정해 루틴이 재생성된 경우에만** 발생한다
- **남편 초대 알림은 이 알림함에 포함하지 않는다.** 초대 알림은 ThinQ 서비스 내 알림이며(F1-1-H), 남편은 연동 전이라 PLM 알림함에 접근할 수 없다
- 알림 클릭 시: 레포트는 해당 날짜 레포트로, 가사 요청은 카드에서 바로 확인 후 확인→완료 상태 전이, 루틴 변경은 캘린더 화면의 **변경된 루틴 요약**으로 이동하며 변경된 항목을 **배너 색상**으로 구분해 표시
- 읽지 않은 알림은 목록에서 별도 표시한다
- 한 줄 요약: 알림 벨 = 컨디션 레포트 도착 + 가사 요청 도착 + 루틴 변경 알림함

**F15. 가사 요청 카드 확인**
- 아내가 보낸 가사 요청을 카드 형태로 표시 (요청 이유, 요청 집안일, 필요한 보조 정보)
- 예: "오늘 허리 통증이 있어요. 장보기와 무거운 물건 옮기기를 도와주세요."

**F16. 가사 요청 상태 관리**
- **요청 상태는 `미확인 → 확인 → 완료` 3단계다.**
  - **미확인**: 남편이 아직 요청을 열거나 확인하지 않은 상태
  - **확인**: 남편이 '확인' 버튼을 누른 상태
  - **완료**: 실제 가사 수행 후 '완료했어요' 버튼을 누른 상태
- **거절 상태는 존재하지 않는다.** 거절 버튼을 만들지 않으며, 자동 거절 처리도 하지 않는다. 남편이 확인만 누르고 완료를 누르지 않으면 요청은 계속 **확인 상태로 남고**, 이를 거절로 처리하거나 자동으로 다른 상태로 변경하지 않는다
- 완료 여부는 Household DB에 저장, 아내 화면·캘린더·일일 레포트에 동시 반영
- **상태 변경 시 아내에게 별도 알림을 보내지 않는다.** 아내는 요청 화면에 들어가 현재 상태(확인/완료)를 조회하는 구조다
- 한 줄 요약: 요청 확인 → 가사 수행 → 완료 처리 → DB/레포트 반영(알림 없이 조회 기반 공유)

**F17. 실시간 탭 (아내와 공유)**
- 아내 쪽 F6-1과 동일한 위험 행동 로그를 남편도 하단 메뉴바의 '실시간' 탭에서 함께 조회
- 별도 데이터가 아닌 동일한 당일 로그를 공유 조회하는 구조

**남편용 전체 흐름**
```
(최초) ThinQ 앱에서 초대 알림 수신 → 알림 선택 → 계정 연동 완료 → 캘린더(남편 홈)
오전 레포트 알림 확인 → 캘린더에서 상태 확인
가사 요청 알림 수신 → 카드 확인 → 확인 → 집안일 수행 → 완료했어요 → 캘린더/레포트 반영
실시간 탭에서 위험 행동 로그 조회 (아내와 공유)
```

### 4.3 공통 UI 규칙

개별 기능이 아니라 모든 화면에 공통으로 적용되는 화면 이동 규칙이다.

**하단 네비게이션**

- 하단 메뉴바는 주요 기능 간 이동을 담당한다
- 하단 메뉴를 통해 이동한 경우, 일반 상세 화면처럼 navigation history를 계속 쌓지 않고 **각 메뉴의 최상위 화면으로 이동**하는 것으로 처리한다
- 예: `가사 상세 화면 → 하단 '홈' 선택 → 홈`. 이후 뒤로가기를 눌렀을 때 다시 가사 상세로 돌아가는 구조로 만들지 않는다

**뒤로가기 규칙 (화면 종류별 4종)**

| 구분 | 대상 | 동작 |
|---|---|---|
| A. 일반 상세 화면 | 건강 상세, 메뉴 추천 상세 등 | 바로 이전 화면으로 이동 (예: 건강 상세 → 건강 가이드) |
| B. 최초 프로필 설정 | 프로필 등록 온보딩 단계 | 바로 이전 **Step**으로 이동 (예: 5단계 → 4단계) |
| C. 프로필 수정 모드 | 입력 확인 화면에서 항목을 선택해 진입한 수정 화면 | **수정 내용을 저장하지 않고 기존 값을 유지한 채 입력 확인 화면으로 복귀**. 나머지 프로필 단계를 다시 진행하지 않는다 |
| D. Bottom Sheet / Modal | 수면 환경 설정 바텀시트, 확인 팝업 등 | 현재 페이지를 유지하고 UI만 닫음 (예: 수면 환경 설정 닫기 → 수면 가이드 화면 유지) |

- B와 C를 구분하기 위해 프로필 진입 시 **최초 등록 모드와 수정 모드의 context를 분리**해야 한다(`mode = onboarding` / `mode = edit`)
- 프로필 설정이 최종 완료되지 않은 상태에서 앱을 완전히 종료한 경우, 작성 중이던 Step을 이어서 진행하지 않고 **재진입 시 프로필 1단계부터 다시 시작**한다

## 5. 핵심 가치 제안 (Key Value)

1. **주수 + 컨디션 기반 개인화**: 출산예정일·신체정보·초산/경산·단태/쌍태 + 당일 컨디션을 함께 반영해 임산부마다 다른 생활 루틴을 맞춤 제안
2. **검색 대신 하루 루틴 제공**: 음식·활동·수면·건강관리를 각각 검색하지 않아도 하루 전체를 하나의 루틴으로 통합 제안
3. **정보 제공에서 끝나지 않는 실행 연결**: 추천에 그치지 않고 식사·집안일·수면 관리를 연결된 가전 실행/예약까지 이어주는 행동형 서비스
4. **AI와 대화하며 실시간 재조정**: 루틴/메뉴가 맞지 않으면 챗봇에게 바로 요청해 취향·상태 반영한 재구성 가능

## 7. 기대 효과 및 성과 지표

### 7.1 기대 효과
1. **고객 경험 차별화**: 매일 달라지는 컨디션 반영 루틴 실행으로 임산부 대상 차별화된 가전 사용 경험 제공
2. **생활 데이터 자산 확보**: 컨디션 기록·루틴 실행·가전 사용 패턴 데이터가 ThinQ에 축적, 임신·출산 가구 생활패턴 이해 기반 확보
3. **ThinQ 락인 효과 강화**: 데이터 누적 → 루틴 정교화 → 임신 10개월 내내 지속 사용 → 출산 후 육아 모드로 자연 연장
4. **신규 고객 기반 매출 확대**: 임신·출산기 가전 교체 수요·구매 명분 강화 → 로봇청소기·건조기·공기청정기 등 다품목 구매 가능성 확대

## 8. 향후 확장 전략

1. **고객군 확장**: 임산부에게 검증된 컨디션 기반 루틴을 회복기 산모, 만성질환자, 시니어 등 몸 상태가 매일 달라지는 고객군으로 확장
2. **가전 연동 확장**: 체중계, 수면 센서, 스마트 미러 등 측정 기기 연동 강화 → 사용자 입력 없이도 컨디션 반영 루틴 제공
3. **생애주기 확장**: 임신 → 출산 → 육아로 이어지는 모드 전환을 통해 가족 구성 변화 전체를 함께하는 서비스로 확장

## 9. 제약 및 주의사항

- **남편 연결 해제 기능은 현재 서비스 범위에 없다** — 연결 완료 이후 해당 연결은 유지되는 것으로 처리하며, `연결 해제 → 권한 삭제` 같은 흐름을 임의로 추가해서는 안 된다
- **F6-1 홈카메라 기반 활동 자세 확인은 의료적 위험을 진단하는 기능이 아님** — 신체 부담 가능 행동 패턴 파악 용도로만 사용해야 하며, UI/문구에서 의료 진단으로 오인되지 않도록 명확히 고지 필요. 서비스 문구는 "위험 판정"이나 "질병 진단"이 아니라 "생활 중 부담 가능 행동 감지" 수준으로 표현한다
- 모션 모니터링 데이터는 실시간으로 당일 루틴에 즉시 반영하지 않고, 익일 루틴 생성 시 반영 (오탐에 의한 즉각적 루틴 왜곡 방지)
- 홈카메라를 활용하는 만큼 영상 데이터 프라이버시·보관정책에 대한 별도 정의가 필요 (원문서에 미기재, 구현 전 확정 필요)
- 혈당/체중 등 건강 수치 기반 제안은 의료 자문을 대체하지 않는다는 점을 사용자에게 고지할 필요 (원문서에 명시되지 않아 구현 시 법무/의료 검토 권장)
- **AI 엔진은 서비스의 모든 개인화 판단(루틴 생성, 메뉴 추천, 챗봇 재조정)을 담당하는 핵심 외부 의존 컴포넌트임** — 엔진 응답 지연·실패에 대비한 폴백(이전 루틴 재사용, 기본 템플릿 제공)과 재시도 정책을 사전에 정의해야 함
- AI 엔진의 판단 결과가 의료적 조언으로 오인되지 않도록, 루틴·챗봇 응답 전반에 "의료 자문 대체 아님" 고지를 일관되게 적용해야 함
