# 유스케이스 명세서: ThinQ Pregnancy Life Mode

- 작성 기반: `02_유스케이스다이어그램.md`(5개 액터·UC1~UC17 버전), `01_PRD.md`, `01_MVP.md`
- 대상: 유스케이스 다이어그램에 정의된 UC1~UC17 전체 (UC14 = 알림 확인)
- 표기: "사용자 행동"과 "시스템 반응"을 흐름 항목에서 구분 표기. [사용자] / [시스템] / [외부 시스템]으로 주체를 명시

## UC1. 임산부 프로필 등록

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC1 |
| 유스케이스명 | 임산부 프로필 등록 |
| 액터 | 아내 (Primary) |
| 목적 | 개인화 추천의 기준이 되는 임신 정보를 저장하여 이후 모든 기능에서 활용 가능하게 한다 |
| 사전 조건 | 아내가 회원가입/로그인을 완료한 상태. **진입 시 `mode = onboarding`(최초 등록)과 `mode = edit`(수정) 중 어느 context로 들어왔는지를 구분해 전달해야 한다** — 이 구분에 따라 뒤로가기 동작과 저장 후 복귀 지점이 달라진다 |
| 사후 조건 | 프로필 정보가 저장되고, 이를 기준으로 임신 주수가 계산되어 다른 기능에서 참조 가능한 상태가 된다. **최초 등록인 경우에 한해 완료 직후 남편 계정 초대(UC15) 화면으로 자동 연결된다.** |

**기본 흐름 (mode = onboarding, 최초 등록)**
1. [사용자] 아내가 최초 가입 온보딩 흐름으로 프로필 등록 화면에 진입한다.
2. [사용자] 6단계를 순차로 입력한다. 각 단계 상단에는 전체 6단계 중 현재 위치(n/6)가 진행바로 표시된다.
   1. 출산예정일 — 출산예정일을 모르는 경우 **마지막 생리 시작일(LMP)**을 대신 입력하면 LMP+280일로 자동 산출한다. 둘 중 하나만 입력해도 다음 단계로 진행할 수 있다
   2. 임신 전 신장·체중
   3. 초산/경산
   4. 단태아/다태아
   5. **알레르기** (갑각류·견과류·우유·계란·밀 등 다중 선택, 선택 없이도 진행 가능)
   6. **주의 진단** (임신성 당뇨 경계·빈혈·고혈압 등 다중 선택) 및 진료에서 구두로 들은 안내 내용 **자유 입력("그 외 들은 말")** — 선택 사항
   - ※ 나이는 프로필 항목으로 함께 관리한다.
3. [시스템] 각 단계에서 입력값의 형식과 논리적 유효성을 검증한다.
4. [사용자] 6단계 입력을 마치면 [시스템]은 **입력 내용 확인 화면(W-PROFILE-007)**에 6단계 입력값을 항목별 목록으로 표시한다. 미입력 항목은 빈 값으로 표시한다.
5. [사용자] '완료하고 시작하기'를 선택한다.
6. [시스템] 임신 주수를 계산하고 프로필을 최종 저장한 뒤, 남편 계정 초대(UC15) 화면으로 전환한다.

**대안 흐름**
- A1. 이미 프로필이 등록되어 있는 경우, 아내는 전역 프로필 버튼을 통해 수정 화면으로 진입해 정보를 갱신할 수 있다. [시스템]은 변경된 값을 기준으로 임신 주수를 재계산하고, 저장 후 전역 진입 지점(MENU)으로 복귀한다.
- **A2. (mode = edit, 입력 확인 화면에서의 항목 수정)** 입력 내용 확인 화면에서 특정 항목 행을 선택하면 [시스템]은 해당 단계 화면으로 이동하되, 하단 버튼을 "다음"이 아닌 **"저장"**으로 표시한다.
  - 저장: 변경값을 저장하고 **나머지 단계를 순차로 거치지 않고 곧바로 입력 확인 화면으로 복귀**한다.
  - 뒤로가기: 변경 내용을 저장하지 않고 **기존 값을 유지한 채 입력 확인 화면으로 복귀**한다.
  - 이 규칙은 출산예정일, 신장·체중, 초산/경산, 단태아/다태아, 알레르기, 주의 진단 및 자유 입력 모든 항목에 동일하게 적용된다. **수정 후 전체 프로필 입력 과정을 다시 진행하게 만들어서는 안 된다.**

**뒤로가기 규칙**
- mode = onboarding: 각 단계에서 뒤로가기를 누르면 **바로 이전 Step**으로 이동한다 (예: 5단계 → 4단계).
- mode = edit: 뒤로가기를 누르면 저장 없이 **입력 확인 화면으로 복귀**한다 (A2 참조).

**예외 흐름**
- E1. 출산예정일 등 필수 항목이 누락된 경우, [시스템]은 저장을 거부하고 누락 항목을 안내한다.
- E2. 입력값이 논리적으로 유효하지 않은 경우(예: 비정상적인 날짜), [시스템]은 오류를 표시하고 재입력을 요구한다.
- E3. 저장 중 서버/네트워크 오류가 발생하면 [시스템]은 저장 실패를 알리고 재시도를 안내한다.
- **E4. 프로필이 최종 저장되기 전에 앱을 완전히 종료한 경우, [시스템]은 작성 중이던 Step을 복원하지 않는다.** 재진입 시 프로필 등록 완료 여부를 확인해 미완료 상태이면 **1단계(출산예정일 입력)부터 다시 시작**한다. 즉 4단계에서 종료했다고 해서 4단계로 복귀하지 않으며, 최종 등록이 완료된 이후에만 등록된 프로필 상태로 서비스에 진입한다.

**관련 기능 요구사항 후보**: F1 (임산부 프로필 설정)

## UC2. 오늘의 컨디션 기록

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC2 |
| 유스케이스명 | 오늘의 컨디션 기록 |
| 액터 | 아내 (Primary) |
| 목적 | 당일 신체 상태를 기록하여 AI 엔진의 루틴 판단 입력 데이터로 제공한다 |
| 사전 조건 | 프로필 등록(UC1) 완료, 로그인 상태 |
| 사후 조건 | 당일 컨디션이 일별 데이터로 저장되고, AI 하루 루틴 확인(UC3)에 반영 가능한 상태가 된다 |

**기본 흐름**
1. [사용자] 아내가 컨디션 체크 화면에 진입한다.
2. [사용자] 당일 상태 4종을 입력한다 — **입덧**(5단계), **신체 통증**(허리·골반·다리·손목 **4부위** 각 5단계), **피로감**(5단계), **기분**(5단계).
3. [시스템] 입력값을 당일 날짜 기준으로 저장한다.
4. [사용자] '다음'을 선택하면 [시스템]은 **오늘의 집안일(예정 활동) 선택 화면**으로 이동한다. 아내는 9종 아이콘 카드에서 오늘 예정된 집안일을 복수 선택하거나 목록에 없는 항목을 직접 입력으로 추가한다. 아무것도 선택하지 않아도 다음 단계로 진행할 수 있으나 화면 자체를 건너뛰지는 않는다 (선택값의 활용은 UC3). **이 화면은 루틴 생성 이후에도 다시 진입해 수정할 수 있으며, 수정 시 처리는 A1을 따른다.**
5. [시스템] 컨디션과 선택한 집안일을 묶어 AI 하루 루틴 생성을 요청한다 (UC3 → UC11).
6. [시스템] 루틴 생성이 완료되면 남편용 오전 리포트 생성·전송을 트리거한다 (UC8 연계). 리포트에 4대 가이드 요약이 포함되므로 루틴 생성 완료가 실질 전송 시점이다.

**대안 흐름**
- A1. **오늘의 컨디션과 예정 활동은 루틴 생성 이후에도 수정할 수 있다.** 이미 입력한 경우 [시스템]은 기존 입력값을 불러와 수정 가능한 상태로 표시한다. 수정이 저장되면 [시스템]은 다음을 수행한다.
  1. 변경된 정보를 반영해 **오늘의 루틴을 다시 생성**한다.
  2. 식사·가사·건강·수면 **4종 생활 가이드도 새 루틴에 맞춰 함께 업데이트**한다.
  3. 남편에게 **"아내의 루틴이 변경되었습니다."** 루틴 변경 알림을 전송한다 (UC14 연계).
  - 확정('저장하고 마치기')된 루틴은 갱신 대상이 아니며, 확정 이후의 재체크는 A2를 따른다.
- **A2. 같은 날 '저장하고 마치기'로 루틴을 확정한 이후 다시 컨디션을 체크하는 경우**, [시스템]은 기존 값을 덮어쓰지 않고 **새로운 루틴을 생성**한다. 확정된 루틴에는 새 행동을 이어 붙이지 않는다. 같은 날짜에 생성된 여러 루틴은 **하나의 Daily Report로 통합**된다 (UC7 연계).

**예외 흐름**
- E1. 필수 컨디션 항목이 비어 있는 경우, [시스템]은 저장을 보류하고 입력을 요청한다.
- E2. 저장 중 오류가 발생하면 [시스템]은 입력값을 임시 보관해 데이터 유실을 방지하고 재시도를 안내한다.

**관련 기능 요구사항 후보**: F2 (오늘의 컨디션 체크), F12 (오전 컨디션 레포트 확인, 연계)

## UC3. AI 하루 루틴 확인

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC3 |
| 유스케이스명 | AI 하루 루틴 확인 |
| 액터 | 아내 (Primary), AI 엔진 (연계 — 판단 수행) |
| 목적 | 당일 컨디션·임신 주차·전일 활동 데이터를 AI 엔진이 판단해 생성한 식사/가사/건강/수면 루틴을 확인한다 |
| 사전 조건 | 프로필 등록 완료(UC1). **당일 컨디션 기록(UC2)은 필수 전제가 아니다** — 홈 화면은 컨디션 입력 여부와 무관하게 하나이며, 미입력 시에는 가이드 대신 컨디션 체크 CTA가 노출된다 |
| 사후 조건 | (컨디션 입력 완료 시) 아내가 4개 가이드를 확인한 상태이며, 각 가이드는 루틴 실행 기록(UC6)의 대상이 된다. (컨디션 미입력 시) 아내는 컨디션 체크 CTA만 확인한 상태다 |

**기본 흐름**
1. [사용자] 아내가 하단 메뉴바의 '홈' 탭에 진입한다.
2. [시스템] 상단에 인사말·임신 주차·이번 주차 맞춤 팁을 고정 표시한다.
3. [시스템] 오늘 컨디션 입력 여부를 판단한다.
4. (미입력) [시스템] '오늘의 컨디션 체크하러 가기' CTA 버튼을 표시한다. [사용자]가 CTA를 클릭하면 UC2(오늘의 컨디션 기록)로 이동한다. 이하 흐름은 UC2 완료 후 재진입 시 계속된다.
5. (입력 완료) [시스템] CTA 버튼을 숨기고, 당일 컨디션·임신 주차·전일 누적 활동 데이터를 취합해 AI 엔진(UC11)에 판단을 요청한다.
6. [외부 시스템] AI 엔진이 입력을 바탕으로 식사/가사/건강/수면 4개 가이드를 생성해 반환한다.
7. [시스템] 반환받은 가이드를 웰컴 카드 하단에 스크롤로 이어지도록 표시한다.
8. [사용자] 아내가 생성된 하루 루틴을 확인한다.

**대안 흐름**
- A1. 홈카메라 시스템(UC13)으로부터 전일 활동 데이터가 없는 경우, AI 엔진은 컨디션 입력값만으로 루틴을 생성한다.
- A2. 특정 가이드가 마음에 들지 않는 경우, 아내는 UC4(대화형 재조정) 또는 **바텀시트를 통한 항목별 직접 설정**으로 이동할 수 있다. 수면 환경 설정처럼 바텀시트로 열리는 설정은 새로운 전체 화면으로 이동하지 않으며, **적용·취소·뒤로가기 어느 경우에도 바텀시트만 닫히고 현재 가이드 화면은 그대로 유지**된다.

**예외 흐름**
- E1. AI 엔진 응답이 지연되거나 실패하는 경우(UC11 예외 참조), [시스템]은 오류를 알리고 이전 루틴을 임시 제공하거나 재시도를 안내한다.
- E2. 홈카메라 시스템과의 데이터 연동이 실패한 경우, [시스템]은 해당 데이터 없이 AI 엔진에 판단을 요청하고 정확도 저하 가능성을 사용자에게 고지한다.

**관련 기능 요구사항 후보**: F3 (오늘의 예정 활동 선택), F4 (AI 하루 루틴 생성), F5 (식사 가이드), F7 (건강 가이드), F8 (수면 가이드)

## UC4. AI와 대화하며 루틴 재조정

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC4 |
| 유스케이스명 | AI와 대화하며 루틴 재조정 |
| 액터 | 아내 (Primary), AI 엔진 (연계 — 판단 수행) |
| 목적 | 자연어 대화를 AI 엔진이 해석·판단해 생성된 루틴(특히 식사 가이드)을 현재 상황에 맞게 재조정한다 |
| 사전 조건 | 하루 루틴 생성(UC3) 완료. **진입 경로는 두 가지이며 진입 context를 함께 전달해야 한다** — ① 홈 화면 하단 메뉴바의 '챗봇' 탭 ② 식사 가이드 내부의 추천 메뉴 카드(AI 재조정 바). 같은 챗봇 화면을 쓰더라도 어디에서 진입했는지의 맥락(예: 어떤 끼니를 다시 고르는 중인지)을 화면 상단 배너로 표시하고 대화 시작값으로 AI 엔진에 전달한다 |
| 사후 조건 | 대화 결과가 두 종류의 데이터로 분리 저장된다. **① 일반 대화(conversation history)**: 음식·생활 관련 단순 질문 등은 대화 이력 DB에만 저장되고 **Daily Report에는 직접 반영되지 않으며**, 이후 루틴 추천의 개인화 정보로만 활용된다. **② 루틴 변경 결과(routine event)**: 대화로 인해 현재 루틴이 실제로 변경된 경우에만 변경 결과를 현재 루틴에 저장하고 Daily Report에 반영한다. **대화 원문 자체를 Daily Report에 저장하지 않는다.** 수락/거절 여부는 이후 AI 엔진 추천에 반영될 이력으로 기록된다 |

**기본 흐름**
1. [사용자] 아내가 챗봇에게 현재 상태나 요청 사항을 자연어로 전달한다.
2. [시스템] 입력된 메시지와 프로필·임신 주차·당일 컨디션 맥락을 AI 엔진(UC11)에 전달해 판단을 요청한다.
3. [외부 시스템] AI 엔진이 맥락을 반영해 응답 및 재추천을 생성해 반환한다.
4. [사용자] 아내가 재추천 결과를 확인하고 수락한다.
5. [시스템] 변경된 루틴을 저장하고 수락 이력을 기록한다.

**대안 흐름**
- A1. 재추천 결과도 마음에 들지 않는 경우, 아내는 챗봇에게 다시 요청해 추가 조정을 받을 수 있다.
- A2. 아내가 재추천을 수락하지 않고 기존 루틴을 유지할 수 있다.

**예외 흐름**
- E1. AI 엔진 응답 생성이 실패하거나 시간 초과되는 경우(UC11 예외 참조), [시스템]은 오류를 안내하고 재시도를 요청한다.
- E2. 요청이 서비스 범위를 벗어나는 경우(예: 의료적 진단 요청), AI 엔진은 조정 불가 판단을 반환하고 [시스템]은 전문가 상담을 권고하는 안내를 표시한다.

**관련 기능 요구사항 후보**: F5 (식사 가이드 재추천), F9 (AI 챗봇)

## UC7. 생활 기록 리포트 조회

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC7 |
| 유스케이스명 | 생활 기록 리포트 조회 |
| 액터 | 아내 (Primary) |
| 목적 | 날짜별 컨디션과 루틴 실행 이력을 확인해 임신 기간 전체의 생활 변화 패턴을 파악한다 |
| 사전 조건 | 최소 1일 이상의 루틴 실행 기록(UC6) 존재 |
| 사후 조건 | '저장하고 마치기'를 실행한 경우 **해당 루틴이 확정 상태가 되고** Daily 리포트가 갱신되며 남편에게 전송된다. 이후 캘린더에서 조회하는 동작 자체는 데이터를 변경하지 않는다 |

**기본 흐름**

리포트 생성과 루틴 확정은 **2단계로 분리**된다.

1. [사용자] 아내가 홈 화면에서 **"오늘의 일정 마치기"**를 실행한다.
2. [시스템] 당일 실행 기록을 집계해 Daily 리포트를 생성하고 화면에 표시한다. **이 단계에서는 아직 루틴이 확정되지 않는다.**
3. [사용자] Daily 리포트 화면에서 **"저장하고 마치기"**를 선택한다.
4. [시스템] 해당 루틴을 **확정 상태로 전환**하고, Daily 리포트를 업데이트한 뒤 캘린더에 저장하고 **남편에게 Daily 리포트를 전송**한다.
5. [사용자] 컨디션 캘린더에서 조회할 날짜를 선택한다.
6. [시스템] 해당 날짜의 컨디션, 추천 루틴, 실행 여부, 가전 실행 내역, 가족 분담 내역, **홈캠 관련 주의사항**을 표시한다.

**데이터 규칙 및 제약**
- **날짜 기준 Daily 리포트는 1개다.** 같은 날짜에 여러 루틴이 생성·확정되더라도 리포트를 각각 만들지 않고 하나로 통합한다. 데이터 구조는 `날짜 → Daily Report 1개 → 해당 날짜에 생성된 여러 Routine 및 Routine Event 누적` 형태다.
- **루틴 종료 트리거는 사용자의 '저장하고 마치기' 뿐이다.** 루틴 종료 전 Daily 리포트를 자동 확정하거나, **자정 기준으로 Daily 리포트를 자동 생성해서는 안 된다.**
- 확정된 루틴에는 새로운 행동을 이어 붙이지 않는다. 같은 날 다시 시작하려면 컨디션 체크를 다시 진행해 새 루틴을 생성한다 (UC2 A2).
- 홈캠 정보는 감지 raw data가 아니라 **주의사항 문구 수준**으로만 표시한다. 정확한 기준값·횟수·시간 기준은 추후 백엔드 및 감지 로직 개발 과정에서 정의한다.

**대안 흐름**
- A1. 기록이 없는 날짜를 선택한 경우, [시스템]은 데이터 없음을 표시한다.

**예외 흐름**
- E1. 리포트 데이터 조회 중 서버 오류가 발생하면 [시스템]은 오류를 안내하고 재조회를 요청한다.

**관련 기능 요구사항 후보**: F11 (Daily 리포트와 컨디션 캘린더)

## UC9. 가사 요청 확인 및 처리

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC9 |
| 유스케이스명 | 가사 요청 확인 및 처리 |
| 액터 | 남편 (Secondary), 아내 (요청자) |
| 목적 | 아내가 보낸 가사 요청을 확인하고 처리 상태를 관리해 가족 분담을 완료한다 |
| 사전 조건 | 아내가 가사 요청을 전송함(UC5) |
| 사후 조건 | 요청 처리 상태(확인/완료)가 저장되고 아내 화면·캘린더·리포트에 반영된다 |

**요청 상태 정의**

요청 상태는 `미확인 → 확인 → 완료` **3단계**다.

| 상태 | 의미 |
|---|---|
| 미확인 | 남편이 아직 요청을 열거나 확인하지 않은 상태 |
| 확인 | 남편이 '확인' 버튼을 누른 상태 |
| 완료 | 실제 가사 수행 후 '완료했어요'를 누른 상태 |

**기본 흐름**
1. [사용자] 남편이 알림 벨 또는 카드 목록에서 가사 요청을 확인한다. 이때 요청은 **미확인** 상태다.
2. [사용자] '확인' 버튼을 눌러 상태를 **확인**으로 전환한다.
3. [사용자] 실제 집안일을 수행한다.
4. [사용자] '완료했어요' 버튼을 누르면 [시스템]은 실수 방지를 위해 완료 처리하려는 집안일 내용을 다시 보여주는 확인 팝업을 띄운다.
5. [사용자] 팝업에서 '완료했어요'를 다시 선택하면 [시스템]은 상태를 **완료**로 전환해 저장하고 아내 화면·캘린더·리포트에 반영한다.
6. [시스템] 완료 결과와 반영 위치, 당일 가족 분담 내역(요청받은/확인한/완료한 항목 건수)을 안내 팝업으로 보여준다.

**대안 흐름**
- A1. 남편이 확인만 하고 즉시 수행하지 않는 경우, 요청은 계속 **확인** 상태로 유지된다.
- A2. 4단계 팝업에서 '아직이에요'를 선택하면 기존 확인 상태를 유지한 채 복귀한다.

**제약 (임의 구현 금지)**
- **거절 상태와 거절 버튼은 존재하지 않는다.** 요청을 거절하는 UI를 만들지 않는다.
- 남편이 확인만 하고 완료하지 않은 상태를 **거절로 처리하지 않으며, 자동으로 거절 상태나 다른 상태로 변경해서도 안 된다.** 완료하지 않은 요청은 확인 상태로 계속 남아 있는다.
- 상태가 바뀌었다고 해서 아내에게 별도 알림을 보내지 않는다. 아내는 요청 화면에 들어가 상태를 조회한다 (UC5 연계).

**예외 흐름**
- E1. 남편이 요청을 장시간 확인하지 않는 경우, [시스템]은 **기존 가사 요청 알림의 미읽음 표시를 유지**한다. 미확인 상태를 근거로 **새로운 알림을 추가 생성하지 않는다.**
- E2. 완료 처리 중 저장 오류가 발생하면 [시스템]은 처리 실패를 안내하고 재시도를 요청한다.

**관련 기능 요구사항 후보**: FUC-H-REQUEST-001 (가사 요청 카드 확인), FUC-H-REQUEST-002 (요청 확인 및 완료 처리), FUC-H-REQUEST-003 (가사 요청 완료 결과 안내)

## UC11. 루틴/추천 판단 생성

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC11 |
| 유스케이스명 | 루틴/추천 판단 생성 |
| 액터 | AI 엔진 (외부 시스템) |
| 목적 | 프로필·컨디션·임신 주차·활동 데이터를 종합 판단해 루틴, 메뉴 추천, 챗봇 응답 등 서비스의 모든 개인화 결정을 생성한다. 서비스 내 모든 판단은 이 유스케이스를 통해서만 이루어진다 |
| 사전 조건 | 판단에 필요한 최소 입력(프로필, 당일 컨디션)이 준비되어 있음, AI 엔진 API 인증 상태 정상 |
| 사후 조건 | 판단 결과(루틴 4종 가이드 또는 대화 응답)가 호출한 유스케이스(UC3, UC4)에 반환되어 사용자에게 노출 가능한 상태가 된다 |

**기본 흐름**
1. [시스템] UC3(하루 루틴 확인) 또는 UC4(대화 재조정)로부터 판단 요청이 발생하면, 프로필·컨디션·임신 주차·전일 활동 데이터(홈카메라 시스템 제공분 포함, UC13)를 취합해 AI 엔진에 전달한다.
2. [외부 시스템] AI 엔진이 입력 데이터를 바탕으로 판단 로직을 수행한다.
3. [외부 시스템] AI 엔진이 판단 결과(루틴 가이드 또는 챗봇 응답)를 시스템에 반환한다.
4. [시스템] 반환된 결과를 저장하고 요청한 유스케이스에 전달한다.

**대안 흐름**
- A1. 홈카메라 시스템(UC13)의 활동 데이터가 없는 경우, AI 엔진은 프로필·컨디션 데이터만으로 판단을 수행한다.
- A2. 요청이 식사 가이드 재조정(UC4)인 경우, AI 엔진은 직전 대화 맥락과 사용자의 과거 수락/거절 이력을 추가로 반영한다.

**예외 흐름**
- E1. AI 엔진 API 인증이 만료되었거나 인증 오류가 발생한 경우, [시스템]은 판단 요청을 중단하고 오류를 기록하며, 요청한 유스케이스(UC3/UC4)에 실패를 알린다.
- E2. AI 엔진 응답이 시간 초과되거나 지연되는 경우, [시스템]은 재시도 후에도 실패 시 이전 루틴 또는 기본 템플릿으로 폴백한다.
- E3. AI 엔진이 반환한 결과가 유효하지 않은 형식(스키마 불일치, 빈 응답 등)인 경우, [시스템]은 해당 응답을 폐기하고 폴백 처리 후 오류를 로깅한다.
- E4. 요청 내용이 서비스 판단 범위를 벗어나는 경우(예: 의료 진단 요청), AI 엔진은 "판단 불가" 응답을 반환하고 [시스템]은 전문가 상담 권고 문구를 대신 표시한다.

**관련 기능 요구사항 후보**: F4 (AI 하루 루틴 생성), F5 (식사 가이드), F7 (건강 가이드), F8 (수면 가이드), F9 (AI 챗봇) — 모든 AI 판단 기반 기능의 공통 처리 유스케이스

- E2. ThinQ 외부 API 연동 자체가 실패(인증 만료, 서버 오류 등)하는 경우, [시스템]은 가전 제어 기능 일시 중단을 안내하고 재인증/재시도를 요청한다.
- E3. 가전 제어 권한이 없는 경우(가족 계정 권한 미설정 등), [시스템]은 권한 오류를 안내한다.

## UC13. 활동/자세 데이터 제공

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC13 |
| 유스케이스명 | 활동/자세 데이터 제공 및 위험 행동 로그 조회 |
| 액터 | 홈카메라 시스템 (외부 시스템), 아내 (데이터 주체 겸 조회자), 남편 (조회자, 아내와 동일 로그 공유) |
| 목적 | 일상 속 활동·자세 패턴 중 임계값을 초과해 위험 행동으로 분류된 상황을 로그로 남기고, 이를 실시간 탭에서 아내·남편이 공유 조회하며, AI 엔진의 루틴 판단(UC11)에도 사용할 입력 데이터를 제공한다 |
| 사전 조건 | 홈카메라가 설치되어 있고, 아내가 모션 모니터링 기능 사용에 동의한 상태. 남편이 조회하려면 계정 연동(UC16)이 선행되어야 한다 (※ **Phase 1(MVP) 포함 기능.** 단, 감지 임계값·횟수·시간 기준 등 상세 수치는 확정 대상이 아니며 백엔드 감지 로직 개발 단계에서 정의한다) |
| 사후 조건 | 감지 상황이 로그로 누적되어 실시간 화면에서 **당일 기록**을 조회할 수 있고, 과거 기록은 캘린더의 해당 날짜 Daily Report에서 주의사항 형태로 조회할 수 있으며, 다음 날 AI 엔진의 루틴 판단(UC11 → UC3)에 반영된다 |

**기본 흐름**
1. [외부 시스템] 홈카메라 시스템이 일상 행동·자세 패턴(장시간 서 있기, 반복 숙이기, 물건 들기, 휴식 부족 등)을 상시 감지한다.
2. [시스템] 감지값이 설정된 임계값을 초과하는지 판단한다.
3. [시스템] 임계값을 초과한 경우에만 부담 가능 행동으로 분류해 로그 저장소에 누적 기록한다(정상 범위 활동은 기록하지 않음).
4. [사용자] 로그를 조회한다. **아내와 남편의 진입 경로가 다르다.**
   - **아내**: 하단 메뉴바의 '실시간' 탭으로 직접 진입한다(다른 화면의 하위 메뉴가 아닌 독립 탭).
   - **남편**: 남편 앱에는 하단 메뉴바가 없다. 캘린더(UC10) 화면의 **'실시간 홈캠 신체 정보 보기' 버튼으로만** 진입한다.
   - 진입 경로만 다르고 **조회하는 로그는 동일**하다.
5. [시스템] **당일 누적된 감지 로그 목록만** 시간순으로 표시한다.
6. [시스템] 날짜가 바뀌면 실시간 화면의 조회 범위가 새로운 오늘로 넘어간다. **로그 데이터 자체를 삭제하거나 초기화하지 않는다.** 이전 날짜의 감지 내용은 캘린더 → 날짜 선택 → 해당 날짜 Daily Report의 홈캠 주의사항으로 조회한다(UC7·UC10 연계).
7. [시스템] 다음 날 AI 엔진 판단 요청(UC11) 시 전날 누적 데이터를 함께 전달한다.

**제약 (임의 구현 금지)**
- 실시간 화면은 **오늘 데이터 전용**이다. '최근', '전체', '과거 날짜 선택' 등 **기간 필터를 제공하지 않는다.**
- 감지 기록은 단순 누적 기록이며 다음 기능은 제공하지 않는다 — **기록 삭제, 확인 처리, 읽음/미읽음 처리, 개별 상태 변경.**
- 감지 ON/OFF는 **데이터 수집 여부만 제어**한다. OFF로 전환하면 신규 감지만 중단되고, 이미 저장된 당일 기록과 과거 기록은 삭제되지 않고 그대로 조회할 수 있다.

**대안 흐름**
- A1. 아내 또는 남편이 실시간 화면에서 당일 로그만 확인하고 별도 조치를 취하지 않아도, 데이터는 익일 AI 엔진 판단에 자동 반영된다.
- A2. 남편이 아직 계정 연동(UC16)을 완료하지 않은 경우, 캘린더 화면 자체에 접근할 수 없으므로 실시간 로그 조회 진입점도 노출되지 않고 연동 안내가 표시된다.

**예외 흐름**
- E1. 홈카메라 연결이 끊기거나 데이터 전송이 실패하는 경우, [시스템]은 해당 기간 데이터 없음으로 표시하고 AI 엔진은 컨디션 입력값만으로 판단한다.
- E2. 감지 데이터가 의료적 진단으로 오인될 소지를 방지하기 위해, [시스템]은 화면에 "진단 기능 아님" 안내를 항상 표시한다.
- E3. 사용자가 촬영 동의를 철회하는 경우, [시스템]은 즉시 데이터 수집을 중단하고 컨디션 입력 기반 판단 방식으로 전환한다.

**관련 기능 요구사항 후보**: FUC-B-MOTION-001 (홈카메라 활동 감지 및 누적 알림, 아내·남편 공유 조회, Phase 1 포함)

| 오전 컨디션 리포트 도착 | 아내의 컨디션 체크 완료 후 AI 하루 루틴 생성이 완료되면 자동 생성 | 해당 날짜의 오전 리포트 화면 (UC8) |
| 가사 요청 도착 | 아내가 가사 가이드에서 도움 요청 항목을 전송하면 생성 | 가사 요청 카드 화면 (UC9) |
| **루틴 변경** ("아내의 루틴이 변경되었습니다.") | 아내가 오늘의 컨디션 또는 예정 활동을 수정해 루틴이 다시 생성되면 자동 생성 (UC2 A1) | 캘린더 화면 → 해당 날짜의 **변경된 루틴 요약** |

**기본 흐름**
1. [사용자] 남편이 캘린더 화면 우측 상단의 알림 아이콘을 선택해 알림 화면에 진입한다.
2. [시스템] 아내와 관련된 알림을 시간순으로 표시하고, 읽지 않은 알림은 별도 표시한다.
3. [사용자] 알림 항목을 선택한다.
4. [시스템] 알림 종류에 따라 오전 리포트 화면(UC8), 가사 요청 카드 화면(UC9), 또는 캘린더의 변경된 루틴 요약으로 이동시키고 해당 알림을 읽음 처리한다.
5. (루틴 변경 알림인 경우) [시스템] 요약 레포트에서 **변경된 항목을 배너 색상으로 구분해 표시**한다. 변경 전/후 값을 나열하지 않으며, 여러 번 수정된 경우 최신 변경 기준으로 표시한다.

**제약 (임의 구현 금지)**
- **모든 상태 변화가 알림을 발생시키지는 않는다.** 가사 요청의 미확인·확인·완료 등 **상태 변화를 근거로 새로운 알림을 생성하지 않는다.** 해당 상태는 요청 화면과 아내 화면에서 조회하는 구조다(UC9 제약, UC5 연계). 루틴 변경 알림은 이와 별개로, 아내의 **입력값 수정으로 루틴이 재생성된 경우에만** 발생한다.
- **남편 초대 알림은 이 목록에 포함하지 않는다.** 초대 알림은 ThinQ 서비스 내 알림이며(UC16), 남편은 연동 전이라 PLM 알림함에 접근할 수 없다.

**대안 흐름**
- A1. 남편이 알림을 거치지 않고 캘린더(UC10)에서 날짜를 선택해 직접 리포트를 조회할 수 있다.

**예외 흐름**
- E1. 알림 전송이 실패한 경우에도 리포트·요청 데이터 자체는 생성되어 캘린더와 요청 화면에서 조회 가능하나, 즉시 인지가 지연될 수 있음을 고지한다.

**관련 기능 요구사항 후보**: FUC-H-NOTI-001 (통합 알림 목록 표시)

## UC15. 남편 계정 초대

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC15 |
| 유스케이스명 | 남편 계정 초대 |
| 액터 | 아내 (Primary, 발송자), 남편 (초대 대상) |
| 목적 | 남편을 ThinQ 앱에 초대해 계정을 연동함으로써 가족 공유 기능(오전 리포트·가사 요청·실시간 탭 등)을 사용할 수 있게 한다 |
| 사전 조건 | (자동 진입) 아내가 임산부 프로필을 최초로 등록 완료한 직후, 또는 (수동 진입) 남편 계정이 아직 연동되지 않은 상태에서 아내가 전역 프로필 버튼 메뉴의 '남편 초대'를 선택한 경우 |
| 사후 조건 | 1회성 초대 토큰이 생성되고 **남편의 ThinQ 앱으로 초대 알림이 발송**되며, 남편이 이를 선택하면 초대 수락 및 계정 연동(UC16)으로 이어진다 |

**기본 흐름**
1. [시스템] 다음 두 경로 중 하나로 남편 초대하기 화면을 표시한다(연결 시 가능한 기능 안내 포함).
   - 자동: 프로필 최초 등록 완료 직후
   - 수동: 아내가 전역 프로필 버튼 메뉴에서 '남편 초대'를 선택 (남편 미연동 상태에서만 이 메뉴 항목이 노출됨)
2. [사용자] 아내가 '초대장 보내기'를 클릭한다.
3. [시스템] 1회성 초대 토큰을 생성하고, **남편의 ThinQ 앱으로 초대 알림 발송을 요청**한다. 이 알림은 **ThinQ 서비스 내 알림**이며 PLM 알림함(UC14)과 무관하다.
4. [시스템] 완료 안내 후, 자동 진입이었다면 **홈 화면(컨디션 체크 전 상태)**으로, 수동 진입이었다면 이전 화면으로 이동한다.

**대안 흐름**
- A1. 아내가 '나중에'를 클릭하면 [시스템]은 초대를 건너뛴다. **'초대장 보내기'와 '나중에'는 선택 결과와 무관하게 동일하게 홈 화면(컨디션 체크 전 상태)으로 이동**하며, 이동 지점이 서로 다르지 않다. '나중에'를 선택한 경우 남편이 연동되기 전까지 전역 프로필 버튼 메뉴에 '남편 초대' 항목이 계속 노출되어 언제든 재시도할 수 있다.

**예외 흐름**
- E1. 초대 토큰 생성 또는 ThinQ 알림 발송 요청에 실패하는 경우, [시스템]은 오류를 안내하고 재시도를 요청한다.
- E2. 남편 계정이 이미 연동된 상태에서는 전역 프로필 버튼 메뉴에 '남편 초대' 항목 자체가 노출되지 않아 이 유스케이스에 재진입할 수 없다.

**관련 기능 요구사항 후보**: F1-1 (남편 초대하기), FUC-W-INVITE-002 (전역 프로필 버튼을 통한 재진입)

## UC16. 초대 수락 및 계정 연동

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC16 |
| 유스케이스명 | 초대 수락 및 계정 연동 |
| 액터 | 남편 (Primary) |
| 목적 | 남편이 ThinQ 앱에 도착한 초대 알림을 통해 아내 계정과 연동하고, 남편용 기능을 사용할 수 있는 상태가 된다 |
| 사전 조건 | 아내가 초대를 발송한 상태(UC15). 남편이 ThinQ 계정에 로그인되어 있어야 한다 |
| 사후 조건 | 남편 계정이 아내 계정과 연동되어 오전 리포트·가사 요청·실시간 로그 등 남편용 기능 접근이 가능해진다 |

**기본 흐름**
1. [시스템] 남편의 **ThinQ 앱에 초대 알림이 도착**한다. 이는 ThinQ 서비스 내 알림이며 PLM 알림함(UC14)과 무관하다.
2. [사용자] 남편이 초대 알림을 선택한다.
3. [시스템] 초대 토큰을 검증하고 남편 계정을 아내 계정과 연동한다.
4. [시스템] 연동 완료 후 남편용 홈 화면인 **캘린더 화면**으로 이동한다.

**대안 흐름**
- 없음

**예외 흐름**
- E1. 초대 토큰이 만료되었거나 이미 사용된 경우, [시스템]은 연동 실패를 안내하고 아내에게 재초대를 요청하도록 안내한다.
- E2. 해당 남편 계정이 이미 다른 아내 계정과 연동되어 있는 경우, [시스템]은 중복 연동 불가를 안내한다.
- E3. 연동 처리 중 서버 오류가 발생하면 [시스템]은 실패를 안내하고 재시도를 요청한다.

**관련 기능 요구사항 후보**: FUC-H-INVITE-001 (초대 수락 및 계정 연동). 미반영: 진입 버튼만 노출, 실제 수락 화면은 프론트엔드 구현 대상 아님(팝업 "개발중입니다" 안내로 대체)

## UC17. PLM 서비스 진입 및 분기

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC17 |
| 유스케이스명 | PLM 서비스 진입 및 분기 |
| 액터 | 아내, 남편 (각자 자신의 ThinQ 앱에서 독립적으로 수행) |
| 목적 | ThinQ 메인 화면에서 Pregnancy Life Mode 탭에 진입할 때마다 최초 사용자인지 기존 사용자인지를 판단해, 온보딩 또는 홈 화면으로 자동 라우팅한다 |
| 사전 조건 | 사용자가 ThinQ 계정에 로그인되어 있어야 한다. **Pregnancy Life Mode 진입점(홈 배너·메뉴 항목)은 ThinQ 계정 로그인 상태에서만 노출되며, 서비스를 해지한 경우 배너와 메뉴 항목이 모두 미노출된다.** 남편의 경우 **초대 수락 및 계정 연동(UC16)이 선행**되어야 이 유스케이스가 의미를 갖는다 |
| 사후 조건 | 사용자가 자신의 상태에 맞는 화면(온보딩 또는 홈)에 도달한 상태가 된다 |

**기본 흐름**
1. [사용자] 아내 또는 남편이 다음 두 경로 중 하나로 Pregnancy Life Mode를 선택한다.
   - **① ThinQ 홈 배너**: ThinQ PLAY 배너 하단에 노출되는 Pregnancy Life Mode 배너의 '시작하기'
   - **② ThinQ 메뉴 리스트**: 제품 및 앱 활용 > PLM (신규 기능은 NEW 배지로 표시)
2. [시스템] 아내인 경우 임산부 프로필 등록 여부를, 남편인 경우 아내 계정과의 연동 완료 여부를 조회한다.
3. (미완료) [시스템] 온보딩 화면으로 이동한다 — 아내는 임산부 프로필 등록(UC1)으로 이동한다. **남편은 ThinQ 초대 알림을 통한 연동(UC16)으로만 서비스에 진입할 수 있으므로**, 연동 전 상태에서는 초대가 필요하다는 안내만 표시하고 별도 가입 절차로 진행하지 않는다.
4. (완료) [시스템] 홈 화면으로 이동한다 — 아내는 AI 하루 루틴 홈(UC3)으로, **남편은 초대 수락으로 연동을 마친 상태이므로 캘린더 화면(남편 홈, UC10)**으로 이동한다.

**대안 흐름**
- A1. 아내가 최초 등록을 완료한 직후 다시 PLM 탭에 진입하면, 이후로는 항상 홈 화면(4번 분기)으로 진입한다.
- A2. 남편이 아내의 초대를 받지 못한 상태에서 PLM 탭에 최초 진입하면, 온보딩 화면 대신 "초대가 필요합니다" 안내만 표시하고 별도 가입 절차로 진행하지 않는다.

**예외 흐름**
- E1. 가입/연동 상태 조회 중 서버 오류가 발생하면 [시스템]은 오류를 안내하고 재시도를 요청한다.

**관련 기능 요구사항 후보**: FUC-B-ENTRY-001 (PLM 진입 분기)
