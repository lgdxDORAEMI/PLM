# MVP 정의: ThinQ Pregnancy Life Mode

> 참고: 원본 기획서(`1차문서.pdf`)에는 MVP 단계 구분이 별도로 명시되어 있지 않습니다.
> 아래 스코프는 기획서가 제시한 **우선순위 근거(기회영역 분석 — Actor 1 Action 1·2가 가장 중요도 높은 underserved 영역)** 와
> **핵심 가치 제안 4가지**를 기준으로, 검증 가능한 최소 단위를 판단해 구성한 제안입니다. 실제 착수 전 팀 논의로 확정이 필요합니다.

---

## 1. MVP 목표

기획서가 검증하고자 하는 핵심 가설은 다음과 같습니다.

> 임신·출산 전환가구는 달라진 생활조건에 맞는 생활관리 방법을 판단하고 실행하는 데 어려움을 겪을 것이다.

이 가설을 최소 비용으로 검증하려면, **"주수+당일 컨디션 기반으로 하루 루틴을 자동 생성해주고, 실행 여부를 기록한다"** 는
핵심 루프 하나만 완성도 있게 만들고, 하드웨어·플랫폼 통합이 필요한 요소는 이후 단계로 미루는 것이 타당합니다.

**MVP 핵심 질문**: 사용자가 매일 컨디션을 입력하고, AI가 생성한 루틴을 실제로 실행/기록하는가? (검색 대신 루틴을 받아들이는가?)

> **AI 엔진은 MVP의 최우선 의존 컴포넌트입니다.** 서비스의 모든 판단(루틴 생성, 메뉴 추천, 챗봇 재조정)은 AI 엔진이 수행하며,
> 아내/남편 앱은 이 판단 결과를 보여주고 사용자 입력을 AI 엔진에 전달하는 역할만 합니다. 따라서 MVP 착수 시 화면 개발보다
> **AI 엔진 연동(프롬프트 설계, 입력 데이터 구조, 응답 스키마, 실패 시 폴백)을 최우선으로 검증**해야 합니다.

## 2. MVP 범위

### 2.1 포함 (아내용)

| 기능 | 근거 |
|---|---|
| F1. 임산부 프로필 설정 (최초 등록/수정, 전역 프로필 버튼 포함) | 개인화의 기반 데이터, 없으면 아무 기능도 동작 불가 |
| F1-1. 남편 초대하기 (링크 생성/전송, 나중에 건너뛰기) | 남편 앱 전체(F12~F16)가 계정 연동을 전제로 하므로 온보딩 단계에서 필수. "링크 보내기"만 구현하고 실제 전송 채널(SMS/카카오톡 등)은 OS 표준 공유 시트로 위임해 구현 비용 최소화 |
| F1-1 재진입(전역 프로필 버튼의 '남편 초대' 메뉴) | '나중에' 건너뛴 사용자의 유일한 재초대 경로. 없으면 최초 온보딩에서 스킵한 사용자는 영구히 남편 앱을 못 씀 → 가족 공유 가치 제안(핵심가치 3번) 이탈로 직결되어 MVP 필수 |
| F2. 오늘의 컨디션 체크 | 핵심 가설 검증에 필수 입력 |
| F3. 오늘의 예정 활동 선택 | 가사 루틴 조정의 입력값, 구현 비용 낮음(카드 선택 UI) |
| F4. AI 하루 루틴 생성 (식사/가사/건강/수면 4개 가이드, 텍스트 기반) | 서비스의 핵심 가치 제안 1·2번(개인화, 검색 대신 루틴) 검증 대상 |
| F5. 식사 가이드 (추천 + 챗봇 재추천) | Actor1-Action1(입덧/식사)이 최우선 underserved 영역으로 지목됨 |
| F7. 건강 가이드 (스트레칭/산책 추천, 완료 체크) — **단, 부위 우선순위는 모션 모니터링 없이 컨디션 입력 기반으로 단순화** | Actor1-Action2(통증/자세) 커버, 모션 모니터링(F6-1) 없이도 컨디션 텍스트 입력만으로 최소 기능 제공 가능 |
| F8. 수면 가이드 (루틴 제안 + 완료 체크) — **단, 관절 데이터 기반 자세 추천은 제외, 컨디션 입력 기반으로 단순화** | Actor1-Action5(수면) 커버 |
| F6. 가사 가이드 & 가족 분담 (카드 전송까지) | 핵심 가치 제안 3번(가족 협력) 및 남편 앱과의 연결고리, 구현비용 대비 체감가치 높음 |
| F9. AI 챗봇 (식사 가이드 재조정 한정) | 핵심 가치 제안 4번(실시간 재조정) 검증에 필요한 최소 범위. 전체 루틴 자유 대화형 조정은 Phase 2로 이연 |
| F10. 루틴 실행 및 완료 기록 (직접 행동 + 남편 요청만, 가전 실행 기록은 제외) | 실행률 측정은 MVP 핵심 지표 |
| F11. Daily 리포트 & 컨디션 캘린더 (가전 작동 이력·모션 데이터 요약 제외, 나머지는 포함) | 데이터 축적 자체가 락인 효과의 핵심, 리텐션 유도 요소 |

### 2.2 포함 (남편용)

| 기능 | 근거 |
|---|---|
| F1-1-H. 초대 수락 및 계정 연동 | 남편 앱의 모든 기능이 이 연동을 전제로 함, 온보딩 필수 |
| F12. 오전 컨디션 레포트 확인 | 가족 공유 가치 제안 검증에 필요한 최소 기능 |
| F13. 캘린더 | 남편 앱의 메인 화면, F11과 데이터 연동 구조 공유 가능 |
| F15. 가사 요청 카드 확인 | 가족 분담 흐름의 핵심 |
| F16. 가사 요청 상태 관리 (확인→완료) | F6의 카드 전송과 짝을 이루는 필수 기능 |
| F14. 상단 알림 벨 (앱 내 뱃지/리스트 수준, 푸시는 Phase 2 가능) | 알림 없이는 남편 앱 재방문 유인이 없어 최소 수준 포함 |

### 2.3 제외 (Phase 2 이후)

| 기능 | 제외 사유 |
|---|---|
| F6-1. 실시간 탭 — 위험 행동 로그 (모션 모니터링, 아내·남편 공유 조회 포함) | 하드웨어(홈카메라) 의존성 + 임계값 기반 위험 행동 판단 알고리즘 자체가 별도 R&D 과제 수준. 의료 오인 소지 관련 UX/법무 검토도 선행되어야 함. **MVP 단계에서는 F2 컨디션 체크(텍스트/선택 입력)만으로 건강·수면 가이드를 대체 생성**. 남편 쪽 공유 조회(F17)도 동일하게 제외 |
| 가전 자동 실행 연동 (F6, F8 내 "연결 가전 실행") | ThinQ 디바이스 API 연동 및 실제 가전 제어 검증에 별도 리소스 필요. MVP는 "가전 수행 추천"까지만 제공하고 실제 실행은 사용자가 수동으로 하도록 함 |
| F9 챗봇의 전체 루틴 자유 대화 조정 (가사/건강/수면까지 자연어로 재조정) | 식사 가이드 재조정만으로도 핵심 가치(4번) 검증 가능. 전체 루틴 대상 확장은 대화 설계·의도 분류 복잡도가 높아 Phase 2로 이연 |
| Daily 리포트의 모션 데이터 요약(관절 부담 초과 횟수 등) | F6-1 제외에 따른 연쇄 제외 |
| 알림 벨의 실시간 푸시 알림 인프라 | 앱 내 알림 리스트로 MVP 가설 검증 가능, 푸시 인프라는 별도 이슈 |

## 3. MVP 사용자 흐름

### 아내
```
(최초 1회) 프로필 등록 → 남편 초대하기(링크 보내기 또는 나중에)
프로필 설정/수정(전역 버튼) → 아침 컨디션 체크 → 오늘 예정 활동 선택 → AI 루틴 생성
→ 식사·가사·건강·수면 가이드 확인 → (필요 시) 남편에게 가사 요청 카드 전송
→ 각 루틴 완료 체크 → 하루 일정 끝내기 → 캘린더에 저장
```

### 남편
```
(최초 1회) 초대 링크 수락 → 계정 연동
오전 레포트 알림 확인 → 가사 요청 카드 확인 → 확인 → 수행 → 완료했어요
→ 캘린더에서 이력 확인
```

## 4. MVP 성공 지표 (제안)

원문서는 최종 성과 지표(ThinQ 사용 지속, 데이터 축적, 가전 구매 확대 등)를 제시하지만 이는 장기 지표입니다.
MVP 단계에서는 아래와 같은 선행 지표로 가설 검증을 판단하는 것을 제안합니다.

| 지표 | 검증 대상 |
|---|---|
| 컨디션 체크 D7/D30 리텐션 | "매일 입력할 만큼 가치가 있는가" (핵심 루프 지속성) |
| AI 루틴 중 실제 완료 체크 비율 | "제안이 실행 가능한 수준으로 개인화되었는가" |
| 식사 가이드 챗봇 재추천 사용률 | "AI 재조정 가치 제안이 통하는가" |
| 가사 요청 카드 전송→완료 전환율 | "가족 분담 흐름이 실제로 작동하는가" |
| 남편 앱 오전 레포트 확인율 | "파트너 참여가 유지되는가" |

## 5. 리스크 (MVP 한정)

- 모션 모니터링 없이 건강/수면 가이드를 컨디션 입력만으로 생성할 경우, 개인화 정밀도가 원 기획 대비 낮아짐 → Phase 2에서 F6-1 도입 시 가이드 품질이 유의미하게 개선됨을 사용자가 체감할 수 있도록 설계 필요
- 가전 자동 실행이 빠진 상태에서는 "정보 제공에서 끝나지 않는 실행 연결"이라는 핵심 가치 제안 3번이 부분적으로만 검증됨 → MVP 지표 해석 시 이 점을 감안해야 함
- **AI 엔진(외부 API/LLM) 의존 리스크**: 응답 지연·실패·비용이 서비스 전체 체감 품질을 좌우함 → MVP에서는 정교한 캐싱·재시도 로직 없이 최소 폴백(이전 루틴 재사용)만 확보하고, 고도화는 Phase 2로 이연
