# 임산부 부담 자세 모니터링 알림 기능 — 프로토타입 구현 계획서 (v3)

> **현행 계획 문서.** 이전 판(v1, v2)은 삭제했으며, 결정 경위는 아래 개정 이력과 §2.1의 미채택 사유 표에 정리되어 있다.
>
> **개정 이력**
>
> - v1: 규칙 기반 판정 방식 확정, RHM-HAR-SK 행동분류 모델 미채택 결정
> - v2: aihub 관절추론모델(NHSE 27-keypoint) 일반화 실패 확인 → mmpose COCO 사전학습 HRNet으로 교체
> - v3: 스켈레톤 추출 백본을 MediaPipe Pose로 최종 확정. WSL 의존 제거, Windows 네이티브 환경으로 전환. 개인 캘리브레이션 방식 신규 도입.
> - **v3 갱신(현재)**: 프로토타입 구현 결과를 실제 배치 구조에 맞춰 §6에 반영(독립 디렉토리 대신 기존 PLM 구조에 통합 배치). Frankel 등 코호트 연구 기반 **누적 전방굴곡 위험 규칙**을 §2.5로 신규 문서화(코드에는 이미 구현되어 있었으나 계획서에 누락되어 있던 내용).

## 0. 문서 목적

"모션 모니터링 기반 임산부 부담 자세 알림 기능"를 **시연 가능한 프로토타입**으로 구현하기 위한 개발 계획을 정리한다. 실서비스(다중 카메라, ThinQ 앱 연동) 범위는 §9 향후 확장 계획으로 분리하고, 본 문서는 **단일 카메라 + 독립 데모 앱** 기준으로 작성한다.

---

## 1. 서비스 정의 및 스코프

### 1.1 서비스 포지셔닝

- 본 기능은 **"임산부 위험 자세 진단 AI"가 아니라 "임신 중 부담이 될 수 있는 자세·행동 패턴 탐지 및 알림"** 으로 정의한다.
- 임산부 전용 학습 데이터가 없고 의학적 표준 위험표도 확립되어 있지 않으므로, 판정 결과는 의료적 진단이 아닌 **관찰된 자세 사실 기반의 참고 정보**로만 제공한다.
- 모든 안내 문구는 확정적 위험도(%) 표현을 지양하고, 관찰된 수치(반복 횟수, 지속시간, 각도)와 문헌 근거(NIOSH 등)를 함께 제시하는 서술형으로 작성한다.

### 1.2 프로토타입 범위 (Scope)

| 항목           | 프로토타입                     | 향후 실서비스                     |
| -------------- | ------------------------------ | --------------------------------- |
| 카메라 수      | 1대                            | 가정 내 다수 카메라               |
| 앱 연동        | 신규 독립 앱 (자체 UI)         | ThinQ 앱 통합                     |
| 처리 위치      | 로컬 PC 1대 (온디바이스)       | 엣지(카메라/허브) + 클라우드 분리 |
| 인물 다중 추적 | 불필요 (단일 인물 고정)        | 다중 카메라 인물 매칭/재식별      |
| 리포트 발송    | 수동 트리거 또는 데모 시나리오 | 실제 야간 스케줄러                |

### 1.3 프로토타입 핵심 기능 (MVP)

1. 카메라 영상에서 실시간으로 부담 가능 자세 감지
2. 특정 자세가 임계시간 이상 지속되면 앱 내 실시간 경고 알림
3. 하루(또는 데모 세션) 동안의 감지 이력을 집계하여 "일일 리포트" 형태로 앱에 표시

## 2. 기술 방식 결정 및 근거

### 2.1 스켈레톤 추출 백본: MediaPipe Pose (최종 확정)

### 2.2 판정 방식: 규칙 기반 (별도 학습 없음)

**MediaPipe Pose는 관절 좌표만 출력하며, "이 자세가 부담되는가"에 대한 판단 로직은 포함하지 않는다.** 해당 판정 레이어는 본 프로젝트에서 직접 구현한다.

**학습 모델을 두지 않는 근거**

1. **자세 판정은 기하학 계산으로 충분** — 몸통 굴곡각, 무릎각, 지속시간, 반복 횟수는 좌표로부터 삼각함수·타이머로 직접 산출 가능하며, 학습이 필요한 문제가 아니다.
2. **학습에 필요한 정답 라벨이 존재하지 않음** — "이 자세가 임산부에게 실제로 무리였다"는 라벨이 달린 공개 데이터셋이 없으며, 주수별 표준 위험표도 의학적으로 확립되지 않았다.
3. **설명 가능성 확보** — "NIOSH 권고 기준에 따라 판정"이 "AI가 학습해서 판단"보다 근거 제시와 책임 범위 설정에 유리하다.

### 2.3 개인 맞춤화: 캘리브레이션 방식 (신규 — v3)

타겟 사용자에 맞춘 판정은 **학습이 아닌 개인 기준선(baseline) 설정**으로 구현한다.

- 앱 최초 설정 시 사용자가 편한 자세로 수 초간 서 있는 상태를 기록하여 **개인 기본 자세 각도**를 저장
- 이후 판정은 절대 각도가 아니라 **개인 기준선 대비 편차**로 계산
- 임신 진행에 따른 체형 변화를 반영하기 위해 주기적 재캘리브레이션 안내
- 근거: 연구보고서에서도 "일반 성인과 비교해 자세가 다르다는 이유만으로 비정상 분류하지 말고, 같은 사람의 과거 기록과 비교하라"고 권고

### 2.4 MVP 판정 대상 자세 (3종)

| 우선순위 | 자세/동작                         | 판정 신호                                  | 문헌 근거                                                    |
| -------- | --------------------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| 1        | Bending (허리 숙임)               | 몸통 축 굴곡각이 임계값 이상으로 유지/반복 | NIOSH 반복적 허리 숙임 권고                                  |
| 2        | Standing (장시간 기립)            | 고관절·무릎각이 직립 범위로 장시간 유지   | NIOSH 장시간(3시간+) 기립 권고                               |
| 3        | Sitting Down / Standing Up (전환) | 무릎각의 급격한 변화 패턴                  | 낮은 의자에서 일어날 때 무릎 모멘트 증가 연구 (Lou 등, 2001) |

> 이 방식은 겉보기 각도만으로 판정하므로, 각도는 유사하나 의도가 다른 동작(바닥 물건 줍기 vs 신발끈 묶기)은 구분하지 못한다. Lifting/Carrying 등 의도 구분이 필요한 항목은 §9 향후 확장으로 분리했다.

### 2.5 누적 전방굴곡 위험 신호 (보조 규칙, 신규 — v3 갱신)

§2.4의 3종 규칙과 별도로 동작하는 **보조 판정 신호**다. §2.4 규칙은 "개인 캘리브레이션 기준선 대비 편차 + 연속 지속시간/최근 반복 횟수"로 판정하는 반면, 이 규칙은 **절대각(개인 기준선 무관) + 자세 전환과 무관하게 끊김 없이 누적되는 시간**을 사용한다는 점에서 근거와 계산 방식이 다르다.

- **문헌 근거**: Frankel 등, *Occupational and Environmental Medicine*, "Occupational standing, walking and forward bending during pregnancy and the risk of miscarriage: a Danish nationwide, register-based cohort study." 덴마크 전국 등록 코호트(임신 803,829건), 가속도계 실측 기준 하루 8시간 근무 중 "30도 이상 전방 굴곡" 누적시간이 1시간 늘어날 때마다 유산 위험 HR 1.36.
- **해석상 주의**: 상관관계 연구이며 인과관계를 확정한 연구가 아니다. 리포트 문구에는 "위험 X%" 같은 확정적 표현을 쓰지 않고, 관찰된 누적시간과 문헌 언급까지만 서술한다 (§8 의료적 판단 금지 원칙과 동일하게 적용).
- **판정 방식**: 몸통 굴곡각이 절대 기준(30도) 이상인 프레임의 시간을, 자세 상태(Standing/Bending/Sitting) 전환과 무관하게 계속 합산한다. 짧은 추적 끊김(가시성 미달 등)은 무시하고 계속 합산하되, 일정 시간 이상 끊기면 그 구간은 "확인되지 않은 시간"으로 보아 누적에서 제외한다(과다 추정 방지를 위한 보수적 처리).
- **데모 축소값**: 실제 연구 기준(누적 1시간 단위)을 시연 시간 내에 보여주기 위해 축소한 값을 사용한다. 실서비스 전환 시 실제 시간 단위(예: 누적 1시간)로 복원해야 한다.
- **라벨 반영**: 누적시간이 임계값을 넘으면 §2.4 규칙의 결과가 Normal/Repeated Load 수준이라도 최소 Prolonged Load로 격상한다. 다만 Sit-to-Stand 전환처럼 더 급성인 High-load Action 이벤트는 덮어쓰지 않는다.
- **구현 위치**: `rules.yaml`의 `cumulative_forward_bend_risk` 항목(절대각·데모 축소 임계값·끊김 허용시간 정의), `rule_engine.py`의 누적 카운터 로직.

### 2.6 부담 라벨 체계

```
Normal → Repeated Load → Prolonged Load → High-load Action
```

### 2.7 주수(삼분기) 정보의 사용 범위

- 삼분기 정보는 **판정 임계값에 직접 반영하지 않는다.**
- 리포트 문구에 "이 시기에는 이런 동작이 문헌상 더 주의가 필요합니다" 형태의 **교육적 코멘트로만 병렬 노출**하며, 탐지 엔진의 판정 로직과는 분리된 모듈로 구현한다.

## 3. Landmark 포맷 및 피처 정의

### 3.1 MediaPipe Pose 33 landmark (주요 항목)

```
11 left_shoulder   12 right_shoulder
13 left_elbow      14 right_elbow
15 left_wrist      16 right_wrist
23 left_hip        24 right_hip
25 left_knee       26 right_knee
27 left_ankle      28 right_ankle
31 left_foot_index 32 right_foot_index
```

- landmark별 **visibility(가시성) 점수** 제공 → 신뢰도 기반 필터링에 활용
- 2D 화면 좌표 외에 **world landmark(3D 미터 단위, 골반 중심 원점)** 도 제공 → 카메라 각도에 덜 민감한 각도 계산에 활용 가능 (개발 중 2D/3D 중 적합한 쪽 선택)

### 3.2 계산할 피처

| 피처          | 계산 방법                                                    |
| ------------- | ------------------------------------------------------------ |
| 몸통 굴곡각   | 어깨 중점(11,12) ↔ 골반 중점(23,24) 벡터와 수직선 사이 각도 |
| 무릎각        | 골반(23/24) - 무릎(25/26) - 발목(27/28) 세 점의 사이각       |
| 좌우 비대칭   | 좌/우 어깨·골반 높이 차, 좌우 무릎각 차이                   |
| 자세 지속시간 | 특정 상태가 연속 유지된 프레임 수 × 프레임 간격             |
| 반복 횟수     | 각도 시계열의 피크(굴곡→복귀) 카운트                        |

> 노이즈 대응: 프레임별 좌표 흔들림이 있으므로 각도 시계열에 **이동평균/저역통과 필터**를 적용한 뒤 판정한다. 미적용 시 반복 횟수가 과다 계수될 수 있다.

## 4. 시스템 아키텍처

```
[웹캠 1대]
      │ 영상 프레임
      ▼
[로컬 프로세스 — Windows 네이티브, 온디바이스]
  1) MediaPipe Pose → 33 landmark 좌표 + visibility
  2) 피처 계산 (몸통 굴곡각 / 무릎각 / 비대칭 / 지속시간 / 반복횟수)
     └ 개인 캘리브레이션 기준선 적용
  3) 규칙 엔진 (NIOSH 기반 threshold table) → 자세 상태 + 부담 라벨
  4) 타이머 (임계시간 도달 여부 판정)
      │
      ├── 임계 이벤트 발생 ──▶ [실시간 경고 알림] → 앱
      │
      ▼
  5) 이벤트 로그 저장 (로컬 DB: 자세유형, 시각, 지속시간, 반복횟수)
      │
      ▼
  6) 일일 집계 + 리포트 문구 생성
      │
      ▼
   [독립 데모 앱] — 실시간 알림 UI + 일일 리포트 화면
```

**네트워크 경계**: 영상 프레임과 landmark 좌표는 기기 밖으로 나가지 않는다. 외부로 전송되는 것은 **이벤트 메타데이터(자세유형·시각·지속시간)뿐**이며, 이는 프라이버시 설계 원칙이자 발표 시 강조할 지점이다.

## 5. 모듈별 구현 계획

### 5.1 카메라 입력 모듈

- 웹캠 1대에서 프레임 스트림 수신 (`cv2.VideoCapture`)
- 향후 다중 카메라 확장을 대비해 `CameraSource` 인터페이스로 추상화

### 5.2 스켈레톤 추출 모듈

- MediaPipe Pose로 프레임별 33 landmark + visibility 추출
- visibility가 낮은 landmark는 후속 계산에서 제외하거나 직전 프레임 값으로 보간

### 5.3 캘리브레이션 모듈 (신규)

- 최초 설정 시 사용자 기본 자세를 수 초간 측정하여 개인 기준선 저장
- 재캘리브레이션 트리거(주기적 안내 또는 수동 실행) 제공

### 5.4 피처 계산 및 자세 상태 판정 모듈

- §3.2 피처 계산 후, 개인 기준선 대비 편차로 정규화
- MVP 3종 자세 상태(Bending / Standing / Sit-to-Stand 전환)를 규칙으로 직접 판정

### 5.5 규칙 엔진 모듈

- NIOSH 및 문헌 기준을 **YAML/JSON threshold table로 외부화** (코드 수정 없이 임계값 튜닝 가능하도록)
- 자세 상태 + 피처값 → 4단계 부담 라벨(§2.6) 매핑
- 복수 조건 동시 충족 시 가장 높은 단계를 채택하는 우선순위 규칙 적용
- §2.5 누적 전방굴곡 위험 신호를 위 판정과 별도 트랙으로 병렬 계산하여, 임계값 초과 시 라벨을 상향(단, Sit-to-Stand 이벤트는 덮어쓰지 않음)
- 삼분기 코멘트는 별도 매핑 테이블로 분리 관리

### 5.6 타이머 / 이벤트 트리거 모듈

- 부담 라벨 유지 시간 누적, 임계시간 도달 시 이벤트 발생
- 짧은 자세 이탈 시 즉시 리셋하지 않는 **유예시간 정책** 적용
- 데모용 임계시간은 10~20초로 단축 설정, 실서비스 기준값은 별도 산정

### 5.7 실시간 알림 모듈

- 로컬 API 또는 WebSocket으로 앱에 이벤트 push
- 동일 유형 반복 알림에 대한 **쿨다운 정책** 적용 (알림 피로도 관리)

### 5.8 이벤트 로그 / 저장 모듈

- 이벤트(자세유형, 발생시각, 지속시간, 반복횟수)를 로컬 DB(SQLite 등)에 누적
- 실시간 알림 발생 여부와 무관하게 감지된 전체 이벤트를 저장 (리포트 집계용)

### 5.9 리포트 생성 모듈

- 이벤트 로그 집계(자세유형별 횟수 / 총 지속시간 / 최장 지속)
- 문구 매핑 테이블 적용, **관찰 → 문헌 근거 → 증상 자가확인 → 조정 제안** 4단 구조로 생성
- 예시: *"낮은 의자에서 일어나는 동작이 오늘 12회 관찰됐습니다. 임신 후기에는 이 동작에서 무릎이 더 많은 역할을 한다는 소규모 연구가 있습니다. 움직일 때 무릎 통증이 있는지 확인하고, 의자 높이와 안정적인 지지면을 조정해보세요."*
- 프로토타입에서는 자정 스케줄러 대신 **수동 트리거 또는 사전 준비된 데모 시나리오 로그**로 즉시 생성

### 5.10 앱 UI 모듈

- 실시간 알림 화면 (경고 팝업/토스트)
- 일일 리포트 화면 (이벤트 요약 + 예방 문구)
- 캘리브레이션 설정 화면
- (선택) 날짜별 히스토리 화면

## 6. 개발 환경

- **OS**: Windows 네이티브 (WSL 불필요)
- **Python**: 3.9~3.11 권장 (MediaPipe 지원 버전 범위 내)
- **주요 패키지**: `mediapipe`, `opencv-python`, `numpy`
- **GPU**: 불필요 (CPU 실시간 처리 가능)
- **작업 디렉토리**: `pregnancy_posture_prototype/`라는 신규 독립 디렉토리 대신, **기존 PLM 리포지토리 구조에 통합 배치**한다 (배치 결정 — v3 갱신). 프로토타입이라도 앱/백엔드가 이미 존재하는 리포지토리이므로, 별도 디렉토리를 새로 파는 대신 기존 `backend`/`frontend`/`tools`/`docs` 경계에 맞춰 넣는 편이 이후 실서비스 통합(§9) 비용을 줄인다.

> v2까지 사용하던 WSL2 + conda(mmpose/mmcv) 환경은 MediaPipe 전환으로 **불필요해졌다.** 다만 aihub 모델 검증 이력 재현이 필요할 경우를 대비해 당분간 삭제하지 않고 보존한다.

## 8. 검증 및 제약사항

- **임산부 대상 검증 데이터 부재**: 정량적 정확도는 일반인 대상 자체 테스트로만 확인하고, 발표 시 이 한계를 명시한다.
- **임산부 체형에서의 landmark 정확도 미검증**: MediaPipe는 임산부 체형 위주로 학습된 모델이 아니다. 배가 나온 체형에서 골반·허리 landmark 정확도가 떨어질 가능성이 있다. 대응으로 **어깨·골반·무릎 등 크고 안정적으로 검출되는 관절 위주로 피처를 설계**하고, 한계를 문서화한다.
- **임계값의 자의성**: 임계시간·유예시간·쿨다운 값은 문헌상 명확한 기준이 없어 자체 설정하며, **파라미터화하여 조정 가능하도록** 구현하고 발표 시 근거 수준을 명시한다.
- **삼분기 코멘트**: "의학적으로 검증된 위험도"가 아니라 "일반적으로 알려진 주의사항 안내"임을 UI에 명시한다.
- **의료적 판단 금지**: "32주이므로 무릎 손상 위험 82%" 같은 확률·진단형 출력은 근거가 없으므로 사용하지 않는다.

## 9. 향후 확장 계획 (보고서 서술용, 프로토타입 범위 외)

- **동작 의도 기반 인식 고도화**: 현재는 기하학적 규칙만으로 판정하여 겉보기 각도가 유사한 동작(바닥 물건 줍기 vs 신발끈 묶기, Lifting/Carrying 등)을 구분하지 못한다. **RHM-HAR-SK**(스켈레톤 시퀀스 + 14개 행동 라벨)를 활용한 ST-GCN/LSTM류 행동 분류 모델 추가로 확장 가능.
- **다중 카메라 지원**: 카메라 간 동일 인물 세션 유지(재식별 또는 활성 카메라 우선순위 규칙), 이중 카운팅 방지 로직.
- **ThinQ 앱 연동**: 이벤트 스키마를 API로 노출하여 외부 앱에서 소비 가능하도록 확장.
- **야간 스케줄러**: 실제 취침 시간대 자동 리포트 발송.
- **임상 검증**: 임산부 실사용자 데이터 확보 시 판정 기준 재검증 및 전문가(산부인과/재활의학/물리치료/인간공학) 검토.
- **누운 자세 모니터링**: NHS의 "16주 이후 장시간 앙와위 주의" 근거에 기반한 별도 카테고리(관절 부담이 아닌 순환계 주의사항으로 분리) 추가 검토.
