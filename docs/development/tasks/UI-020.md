## Entry

Phase 2에서 확정될 역할별 Bottom Navigation의 독립 `실시간` Tab만 허용한다.

## Route

역할별 `/wife/movement`, `/partner/movement`를 사용한다. 두 경로는 동일한 공유 로그 화면을 역할 Context만 달리해 표시하며 기존 Web Demo Route와 동일시하지 않는다.

## Exit

역할별 이전 Tab. 이탈 시 Camera/WebSocket/Timer/Subscription을 정리한다.

## Back Behavior

이전 Tab/화면으로 복귀하며 활성 Resource를 반드시 중지한다. `IndexedStack`에서는 비활성화 감지를 별도로 구현한다.

## Required Components

### Reuse

- 기존 `MovementScreen`, `MovementController`, `MovementOverlayPainter`, Camera/Transport Interface와 Browser Adapter
- 제품 Foundation 완료 후 `AppButton`, `AppCard`, `AppBanner`, `AppShell`, `AppTopBar`, 상태 Component

### New

- `MovementStatusPanel`, `RealtimeAlertCard`
- 당일 Log 조회 State/Service 경계는 Phase 2 계약 후 결정

## UI Structure

```text
Role AppShell
├─ AppTopBar
├─ ResponsivePageContent
│  ├─ non-medical notice
│  ├─ MovementStatusPanel
│  ├─ latest important alert
│  └─ RealtimeAlertCard list
└─ role Bottom Navigation
```

## UI State

- Disconnected / Connecting
- Calibrating / Live
- Empty log
- Error / Permission denied
- Warning/High attention/Resolved
- Loading log

## Interaction

- Tap/Keyboard: 시작/중지, 재시도, Log Detail
- Hover/Focus: Actionable alert
- Scroll: 최신 Alert부터 당일 Log
- Lifecycle: Tab 비활성/Background/Pop 시 Resource 정리

## Data

기존 WebSocket `LiveMessage`/`PostureFrameState`는 현재 데모 계약을 유지한다. 제품 Log는 시간, 행동 유형, 심각도, 안내, 해결 여부를 필요로 하지만 Phase 2 계약 전 Model을 확정하지 않는다.

Data Source: 현재 데모는 `BrowserCameraFrameSource` + `BrowserLiveTransport`; 제품 MockService는 Phase 2 요구 확정 후 추가

Future: 운영 Privacy/다중 사용자/영속화 계약 후 Service/Adapter 교체. 새 Backend를 이 Task에서 구현하지 않는다.

## Responsive

- Mobile-width Web: 상태 → 중요 Alert → 최근 Log 단일 Column
- Tablet-width Web/Desktop: 최대 720px, Camera Preview와 상태가 겹치지 않게 배치

## Accessibility

- Focus: 비진단 고지 → Sensor 상태 → Action → Alert
- Keyboard: 시작/중지/Retry/Detail
- Semantics: 상태·위험도를 Icon+Text로 전달하고 Live Update 빈도 제한
- Tooltip: Icon-only Action
