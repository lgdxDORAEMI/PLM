# UI-012 Partner Household Request

## Goal

파트너가 가사 요청 이유와 항목을 확인하고 `요청됨 → 확인됨 → 완료` 순서로 상태를 변경하도록 구현한다.

## Entry

UI-014 알림, UI-017 오전 Report 또는 UI-018 Calendar Summary.

## Route

`/partner/requests/:requestId`를 사용한다. `requestId`는 내부 Mock ID이며 API 계약이 아니다.

## Exit

상태 전환 후 Detail을 유지하거나 Back으로 실제 진입 화면에 복귀한다.

## Back Behavior

진입 Route로 복귀한다. 제출 중 중복 Action/Pop을 막되 실패 시 사용자를 가두지 않는다.

## UI State

- Loading
- Ready: requested/acknowledged/completed
- Empty/not found
- Submitting / Disabled
- Success
- Error / Retry

## Interaction

- Tap/Keyboard: 확인, 완료했어요, 재시도
- Hover/Focus: 현재 허용 Action
- Transition: Badge/Timeline과 성공 안내

## Data

UI-011의 요청 ID, 이유, Task, 요청자, 시각과 상태를 동일한 Model로 사용한다.

Data Source: `MockHouseholdService` 공유 인스턴스

Future: `ApiHouseholdService`로 교체. 상태 변경 API나 알림을 새로 구현하지 않는다.

## Responsive

- Mobile-width Web: 단일 Column, Action Full Width
- Tablet-width Web/Desktop: 최대 720px, 가변 높이 Card

## Accessibility

- Focus: Context → 요청 → 현재 Action
- Keyboard: 상태 전환
- Semantics: 현재 상태, 마지막 갱신, 허용 Action Live 안내
