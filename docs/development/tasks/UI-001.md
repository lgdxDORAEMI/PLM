## Entry

Bootstrap에서 프로필 없음으로 판정되거나 Wife 전역 Profile Menu에서 `프로필 수정`을 선택한다.

## Route

최초 등록은 `/onboarding/profile`, 수정은 `/wife/profile`을 사용한다. Path가 `ProfileMode`를 결정하며 6개 Step을 별도 URL로 나누지 않는다.

## Exit

최초 등록 완료는 UI-002, 수정 완료는 진입 전 화면으로 이동한다.

## Back Behavior

최초 등록 중 미저장 Draft가 있으면 이탈 확인, 수정 Mode는 변경 여부 확인 후 이전 화면으로 복귀한다.

## UI Structure

```text
Page
├─ AppTopBar
├─ ResponsivePageContent(form)
│  ├─ Progress
│  ├─ Question / Supporting text
│  ├─ Step input or selection
│  ├─ validation/error area
│  └─ Previous / Next or Save
└─ completion ProfileSummary / Dialog
```

## UI State

- Default / Editing
- Loading existing profile
- Selected
- Validation Error
- Submitting / Disabled
- Save Error
- Completed

## Interaction

- Tap/Keyboard: Step 이동, 선택, 저장, Profile Menu
- Input: 날짜, 숫자와 문서상 Profile 항목
- Hover/Focus: 모든 Control
- Transition: Step 변경은 180~240ms, Reduced Motion 존중
- Scroll: 짧은 Viewport와 200% Text에서 CTA 접근 가능

## Data

화면 Model은 문서에 정의된 출산예정일, 나이, 신장, 임신 전 체중, 출산 경험, 태아 수, 알레르기, 주의 진단과 임신 주수/완료 단계만 포함한다.

Data Source: `MockProfileService`

Future: 실제 계약 확정 후 `ApiProfileService`로 교체 예정. 현재 Backend 1·2단계 API를 UI에 직접 연결하거나 3~6단계 Endpoint를 추정하지 않는다. Mock 값을 UI 파일에 하드코딩하지 않는다.

## Responsive

- Mobile-width Web: 20px Padding, 단일 Column, 짧은 Viewport에서만 CTA Sticky
- Tablet-width Web: 최대 560px, 28px Padding, 짧은 2개 선택지만 조건부 2열
- Desktop: 중앙 최대 560px, 불필요한 Side Panel 없음

## Accessibility

- Focus: 제목 → 입력 → 오류 → Navigation 순서
- Keyboard: Tab/Shift+Tab, Enter/Space, 숫자 입력
- Semantics: 현재 Step, 전체 Step, 선택 상태, 필수/오류 상태
- Tooltip: Icon-only Back/Menu
