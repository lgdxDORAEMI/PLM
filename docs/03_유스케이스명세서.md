# 유스케이스 명세서: ThinQ Pregnancy Life Mode

- 작성 기반: `유스케이스다이어그램.md`(AI 엔진 포함 5개 액터·13개 유스케이스 버전), `PRD.md`, `MVP.md`
- 대상: 유스케이스 다이어그램에 정의된 UC1~UC13 전체
- 표기: "사용자 행동"과 "시스템 반응"을 흐름 항목에서 구분 표기. [사용자] / [시스템] / [외부 시스템]으로 주체를 명시

---

## UC1. 임산부 프로필 등록

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC1 |
| 유스케이스명 | 임산부 프로필 등록 |
| 액터 | 아내 (Primary) |
| 목적 | 개인화 추천의 기준이 되는 임신 정보를 저장하여 이후 모든 기능에서 활용 가능하게 한다 |
| 사전 조건 | 아내가 회원가입/로그인을 완료한 상태 |
| 사후 조건 | 프로필 정보가 저장되고, 이를 기준으로 임신 주수가 계산되어 다른 기능에서 참조 가능한 상태가 된다 |

**기본 흐름**
1. [사용자] 아내가 프로필 등록 화면에 진입한다.
2. [사용자] 출산예정일, 나이, 임신 전 키/몸무게, 초산/경산, 단태아/다태아 여부를 입력한다.
3. [시스템] 입력값의 형식과 논리적 유효성을 검증한다.
4. [시스템] 임신 주수를 계산하고 프로필을 저장한다.
5. [시스템] 등록 완료를 안내하고 홈 화면으로 전환한다.

**대안 흐름**
- A1. 이미 프로필이 등록되어 있는 경우, 아내는 수정 화면으로 진입해 정보를 갱신할 수 있다. [시스템]은 변경된 값을 기준으로 임신 주수를 재계산한다.

**예외 흐름**
- E1. 출산예정일 등 필수 항목이 누락된 경우, [시스템]은 저장을 거부하고 누락 항목을 안내한다.
- E2. 입력값이 논리적으로 유효하지 않은 경우(예: 비정상적인 날짜), [시스템]은 오류를 표시하고 재입력을 요구한다.
- E3. 저장 중 서버/네트워크 오류가 발생하면 [시스템]은 저장 실패를 알리고 재시도를 안내한다.

**관련 기능 요구사항 후보**: F1 (임산부 프로필 설정)

## UC2. 오늘의 컨디션 기록

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC2 |
| 유스케이스명 | 오늘의 컨디션 기록 |
| 액터 | 아내 (Primary) |
| 목적 | 당일 신체 상태를 기록하여 AI 엔진의 루틴 판단 입력 데이터로 제공한다 |
| 사전 조건 | 프로필 등록(UC1) 완료, 로그인 상태 |
| 사후 조건 | 당일 컨디션이 일별 데이터로 저장되고, AI 하루 루틴 확인(UC3)에 반영 가능한 상태가 된다 |

**기본 흐름**
1. [사용자] 아내가 컨디션 체크 화면에 진입한다.
2. [사용자] 입덧, 허리/골반 통증, 피로감, 수면 상태 등 당일 상태를 입력한다.
3. [시스템] 입력값을 당일 날짜 기준으로 저장한다.
4. [시스템] 저장 완료 시 남편용 오전 리포트 생성을 트리거한다 (UC8 연계).

**대안 흐름**
- A1. 이미 오늘 컨디션을 입력한 경우, [시스템]은 기존 입력값을 불러와 수정 가능한 상태로 표시한다.

**예외 흐름**
- E1. 필수 컨디션 항목이 비어 있는 경우, [시스템]은 저장을 보류하고 입력을 요청한다.
- E2. 저장 중 오류가 발생하면 [시스템]은 입력값을 임시 보관해 데이터 유실을 방지하고 재시도를 안내한다.

**관련 기능 요구사항 후보**: F2 (오늘의 컨디션 체크), F12 (오전 컨디션 레포트 확인, 연계)

## UC3. AI 하루 루틴 확인

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC3 |
| 유스케이스명 | AI 하루 루틴 확인 |
| 액터 | 아내 (Primary), AI 엔진 (연계 — 판단 수행) |
| 목적 | 당일 컨디션·임신 주차·전일 활동 데이터를 AI 엔진이 판단해 생성한 식사/가사/건강/수면 루틴을 확인한다 |
| 사전 조건 | 당일 컨디션 기록(UC2) 완료 |
| 사후 조건 | 아내가 4개 가이드를 확인한 상태이며, 각 가이드는 루틴 실행 기록(UC6)의 대상이 된다 |

**기본 흐름**
1. [시스템] 컨디션 체크 완료를 감지해 루틴 판단 요청을 시작한다.
2. [시스템] 당일 컨디션, 임신 주차, 전일 누적 활동 데이터를 취합해 AI 엔진(UC11)에 판단을 요청한다.
3. [외부 시스템] AI 엔진이 입력을 바탕으로 식사/가사/건강/수면 4개 가이드를 생성해 반환한다.
4. [시스템] 반환받은 가이드를 화면에 표시한다.
5. [사용자] 아내가 생성된 하루 루틴을 확인한다.

**대안 흐름**
- A1. 홈카메라 시스템(UC13)으로부터 전일 활동 데이터가 없는 경우, AI 엔진은 컨디션 입력값만으로 루틴을 생성한다.
- A2. 특정 가이드가 마음에 들지 않는 경우, 아내는 UC4(대화형 재조정) 또는 설정창을 통한 직접 조정으로 이동할 수 있다.

**예외 흐름**
- E1. AI 엔진 응답이 지연되거나 실패하는 경우(UC11 예외 참조), [시스템]은 오류를 알리고 이전 루틴을 임시 제공하거나 재시도를 안내한다.
- E2. 홈카메라 시스템과의 데이터 연동이 실패한 경우, [시스템]은 해당 데이터 없이 AI 엔진에 판단을 요청하고 정확도 저하 가능성을 사용자에게 고지한다.

**관련 기능 요구사항 후보**: F3 (오늘의 예정 활동 선택), F4 (AI 하루 루틴 생성), F5 (식사 가이드), F7 (건강 가이드), F8 (수면 가이드)

## UC4. AI와 대화하며 루틴 재조정

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC4 |
| 유스케이스명 | AI와 대화하며 루틴 재조정 |
| 액터 | 아내 (Primary), AI 엔진 (연계 — 판단 수행) |
| 목적 | 자연어 대화를 AI 엔진이 해석·판단해 생성된 루틴(특히 식사 가이드)을 현재 상황에 맞게 재조정한다 |
| 사전 조건 | 하루 루틴 생성(UC3) 완료 |
| 사후 조건 | 재조정된 루틴이 반영·저장되고, 수락 여부가 이후 AI 엔진 추천에 반영될 이력으로 기록된다 |

**기본 흐름**
1. [사용자] 아내가 챗봇에게 현재 상태나 요청 사항을 자연어로 전달한다.
2. [시스템] 입력된 메시지와 프로필·임신 주차·당일 컨디션 맥락을 AI 엔진(UC11)에 전달해 판단을 요청한다.
3. [외부 시스템] AI 엔진이 맥락을 반영해 응답 및 재추천을 생성해 반환한다.
4. [사용자] 아내가 재추천 결과를 확인하고 수락한다.
5. [시스템] 변경된 루틴을 저장하고 수락 이력을 기록한다.

**대안 흐름**
- A1. 재추천 결과도 마음에 들지 않는 경우, 아내는 챗봇에게 다시 요청해 추가 조정을 받을 수 있다.
- A2. 아내가 재추천을 수락하지 않고 기존 루틴을 유지할 수 있다.

**예외 흐름**
- E1. AI 엔진 응답 생성이 실패하거나 시간 초과되는 경우(UC11 예외 참조), [시스템]은 오류를 안내하고 재시도를 요청한다.
- E2. 요청이 서비스 범위를 벗어나는 경우(예: 의료적 진단 요청), AI 엔진은 조정 불가 판단을 반환하고 [시스템]은 전문가 상담을 권고하는 안내를 표시한다.

**관련 기능 요구사항 후보**: F5 (식사 가이드 재추천), F9 (AI 챗봇)

## UC5. 가사 도움 요청

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC5 |
| 유스케이스명 | 가사 도움 요청 |
| 액터 | 아내 (Primary, 요청자), 남편 (수신자) |
| 목적 | 현재 상태에서 부담이 큰 집안일을 남편에게 요청해 가족 분담을 실행한다 |
| 사전 조건 | 가사 가이드 생성(UC3) 완료, 남편 계정이 아내 계정과 연동되어 있음 |
| 사후 조건 | 요청이 남편에게 전달되고, 남편의 처리 상태(UC9)와 연동되어 추적 가능한 상태가 된다 |

**기본 흐름**
1. [사용자] 아내가 가사 가이드 중 "가족 분담" 항목에서 요청할 집안일을 선택한다.
2. [사용자] 카드 보내기를 실행한다.
3. [시스템] 요청을 남편 계정으로 전송하고 알림을 생성한다.
4. [사용자] 남편이 요청을 수신한다 (UC9로 이어짐).

**대안 흐름**
- A1. 아내가 여러 항목을 한 번에 선택해 하나의 요청으로 묶어 전송할 수 있다.

**예외 흐름**
- E1. 남편 계정이 연동되어 있지 않거나 연동이 해제된 경우, [시스템]은 전송 불가를 안내하고 계정 연동을 요청한다.
- E2. 알림 전송이 실패하는 경우, [시스템]은 요청 자체는 저장하되 전송 실패를 아내에게 고지하고 재전송을 안내한다.

**관련 기능 요구사항 후보**: F6 (가사 가이드 & 가족 분담)

## UC6. 루틴 실행 기록

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC6 |
| 유스케이스명 | 루틴 실행 기록 |
| 액터 | 아내 (Primary), ThinQ 연동 가전 (연계 입력) |
| 목적 | 하루 루틴 내 각 행동의 실행 여부를 기록해 Daily 리포트와 AI 엔진의 이후 판단에 반영한다 |
| 사전 조건 | 하루 루틴 생성(UC3) 완료 |
| 사후 조건 | 실행/미실행 여부가 하루 기록으로 누적되고, Daily 리포트(UC7) 및 AI 엔진의 다음 판단(UC11) 입력 데이터가 된다 |

**기본 흐름**
1. [사용자] 아내가 직접 수행한 행동(식사, 스트레칭, 산책 등)을 완료 체크한다.
2. [시스템] 가전 수행 항목은 ThinQ 연동 가전에 실행을 요청한다 (UC12).
3. [외부 시스템] ThinQ 연동 가전이 실행 결과를 시스템에 전달하면, [시스템]은 완료 상태를 자동 반영한다.
4. [시스템] 남편 요청 항목은 남편의 처리 상태(UC9)를 받아 완료 상태를 반영한다.
5. [시스템] 모든 실행 기록을 당일 데이터로 누적한다.

**대안 흐름**
- A1. 아내가 완료 체크를 취소하거나 수정할 수 있다.

**예외 흐름**
- E1. ThinQ 연동 가전으로부터 실행 결과 수신이 실패(통신 오류 등)하는 경우, [시스템]은 해당 항목을 "확인 필요" 상태로 표시하고 아내에게 수동 확인을 요청한다.
- E2. 가전 제어 권한이 없거나 가전이 오프라인 상태인 경우(UC12 예외 참조), [시스템]은 실행 불가를 안내하고 직접 수행 대안을 제안한다.

**관련 기능 요구사항 후보**: F10 (루틴 실행 및 완료 기록)

## UC7. 생활 기록 리포트 조회

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC7 |
| 유스케이스명 | 생활 기록 리포트 조회 |
| 액터 | 아내 (Primary) |
| 목적 | 날짜별 컨디션과 루틴 실행 이력을 확인해 임신 기간 전체의 생활 변화 패턴을 파악한다 |
| 사전 조건 | 최소 1일 이상의 루틴 실행 기록(UC6) 존재 |
| 사후 조건 | 조회한 리포트 정보가 화면에 표시된다 (데이터 변경 없음) |

**기본 흐름**
1. [사용자] 아내가 "하루 루틴 끝내기"를 실행한다.
2. [시스템] Daily 리포트를 생성한다.
3. [사용자] 컨디션 캘린더에서 조회할 날짜를 선택한다.
4. [시스템] 해당 날짜의 컨디션, 추천 루틴, 실행 여부, 가전 실행 내역, 가족 분담 내역을 표시한다.

**대안 흐름**
- A1. 기록이 없는 날짜를 선택한 경우, [시스템]은 데이터 없음을 표시한다.

**예외 흐름**
- E1. 리포트 데이터 조회 중 서버 오류가 발생하면 [시스템]은 오류를 안내하고 재조회를 요청한다.

**관련 기능 요구사항 후보**: F11 (Daily 리포트와 컨디션 캘린더)

## UC8. 아내 컨디션 리포트 확인

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC8 |
| 유스케이스명 | 아내 컨디션 리포트 확인 |
| 액터 | 남편 (Secondary) |
| 목적 | 아내의 당일 상태, 예정 활동, AI 루틴 요약을 확인해 하루 상태를 파악한다 |
| 사전 조건 | 아내가 당일 컨디션 체크(UC2)를 완료함 |
| 사후 조건 | 남편이 오전 리포트를 확인한 상태(읽음 처리)가 된다 |

**기본 흐름**
1. [시스템] 아내의 컨디션 체크 완료를 감지해 오전 리포트를 자동 생성한다.
2. [시스템] 남편에게 알림을 전송한다.
3. [사용자] 남편이 알림을 통해 리포트 화면에 진입한다.
4. [시스템] 임신 주수, 당일 컨디션, 예정 활동, 4대 가이드 요약을 표시한다.

**대안 흐름**
- A1. 남편이 알림 대신 캘린더(UC10)에서 직접 오늘 날짜를 선택해 리포트를 조회할 수 있다.

**예외 흐름**
- E1. 남편 계정이 아내 계정과 연동되어 있지 않은 경우, [시스템]은 리포트를 생성하지 않고 접근을 제한한다.
- E2. 알림 전송이 실패한 경우, 리포트 자체는 생성되어 캘린더에서 조회 가능하나 즉시 인지가 지연될 수 있음을 고지한다.

**관련 기능 요구사항 후보**: F12 (오전 컨디션 레포트 확인)

## UC11. 루틴/추천 판단 생성

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC11 |
| 유스케이스명 | 루틴/추천 판단 생성 |
| 액터 | AI 엔진 (외부 시스템) |
| 목적 | 프로필·컨디션·임신 주차·활동 데이터를 종합 판단해 루틴, 메뉴 추천, 챗봇 응답 등 서비스의 모든 개인화 결정을 생성한다. 서비스 내 모든 판단은 이 유스케이스를 통해서만 이루어진다 |
| 사전 조건 | 판단에 필요한 최소 입력(프로필, 당일 컨디션)이 준비되어 있음, AI 엔진 API 인증 상태 정상 |
| 사후 조건 | 판단 결과(루틴 4종 가이드 또는 대화 응답)가 호출한 유스케이스(UC3, UC4)에 반환되어 사용자에게 노출 가능한 상태가 된다 |

**기본 흐름**
1. [시스템] UC3(하루 루틴 확인) 또는 UC4(대화 재조정)로부터 판단 요청이 발생하면, 프로필·컨디션·임신 주차·전일 활동 데이터(홈카메라 시스템 제공분 포함, UC13)를 취합해 AI 엔진에 전달한다.
2. [외부 시스템] AI 엔진이 입력 데이터를 바탕으로 판단 로직을 수행한다.
3. [외부 시스템] AI 엔진이 판단 결과(루틴 가이드 또는 챗봇 응답)를 시스템에 반환한다.
4. [시스템] 반환된 결과를 저장하고 요청한 유스케이스에 전달한다.

**대안 흐름**
- A1. 홈카메라 시스템(UC13)의 활동 데이터가 없는 경우, AI 엔진은 프로필·컨디션 데이터만으로 판단을 수행한다.
- A2. 요청이 식사 가이드 재조정(UC4)인 경우, AI 엔진은 직전 대화 맥락과 사용자의 과거 수락/거절 이력을 추가로 반영한다.

**예외 흐름**
- E1. AI 엔진 API 인증이 만료되었거나 인증 오류가 발생한 경우, [시스템]은 판단 요청을 중단하고 오류를 기록하며, 요청한 유스케이스(UC3/UC4)에 실패를 알린다.
- E2. AI 엔진 응답이 시간 초과되거나 지연되는 경우, [시스템]은 재시도 후에도 실패 시 이전 루틴 또는 기본 템플릿으로 폴백한다.
- E3. AI 엔진이 반환한 결과가 유효하지 않은 형식(스키마 불일치, 빈 응답 등)인 경우, [시스템]은 해당 응답을 폐기하고 폴백 처리 후 오류를 로깅한다.
- E4. 요청 내용이 서비스 판단 범위를 벗어나는 경우(예: 의료 진단 요청), AI 엔진은 "판단 불가" 응답을 반환하고 [시스템]은 전문가 상담 권고 문구를 대신 표시한다.

**관련 기능 요구사항 후보**: F4 (AI 하루 루틴 생성), F5 (식사 가이드), F7 (건강 가이드), F8 (수면 가이드), F9 (AI 챗봇) — 모든 AI 판단 기반 기능의 공통 처리 유스케이스

## UC12. 가전 실행 명령 수행

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC12 |
| 유스케이스명 | 가전 실행 명령 수행 |
| 액터 | ThinQ 연동 가전 (외부 시스템), 아내 (요청 주체) |
| 목적 | 가사 가이드에서 "가전 수행"으로 분류된 항목을 실제 가전 동작으로 연결한다 |
| 사전 조건 | 가사 가이드에 가전 수행 항목이 존재하고, 가전이 ThinQ 계정에 연동되어 온라인 상태임 |
| 사후 조건 | 가전이 실행되고 실행 결과가 시스템에 기록되어 UC6, UC7에 반영된다 |

**기본 흐름**
1. [시스템] 가사 가이드의 가전 수행 항목에 대해 실행 명령을 ThinQ 연동 가전에 전송한다.
2. [외부 시스템] ThinQ 연동 가전이 명령을 수신해 동작을 수행한다.
3. [외부 시스템] 실행 결과(성공 여부, 작동 이력)를 시스템에 전달한다.
4. [시스템] 실행 결과를 루틴 실행 기록(UC6)과 Daily 리포트(UC7)에 반영한다.

**대안 흐름**
- A1. 아내가 자동 실행 대신 수동으로 가전을 직접 조작하는 경우, [시스템]은 가전으로부터의 상태 변경을 감지해 동일하게 기록한다.

**예외 흐름**
- E1. 가전이 오프라인이거나 응답하지 않는 경우, [시스템]은 실행 실패를 기록하고 아내에게 수동 수행을 안내한다.
- E2. ThinQ 외부 API 연동 자체가 실패(인증 만료, 서버 오류 등)하는 경우, [시스템]은 가전 제어 기능 일시 중단을 안내하고 재인증/재시도를 요청한다.
- E3. 가전 제어 권한이 없는 경우(가족 계정 권한 미설정 등), [시스템]은 권한 오류를 안내한다.

**관련 기능 요구사항 후보**: F6 (가전 수행 분류), F8 (수면 가이드 내 연결 가전 실행)

## UC13. 활동/자세 데이터 제공

| 항목 | 내용 |
|---|---|
| 유스케이스 ID | UC13 |
| 유스케이스명 | 활동/자세 데이터 제공 |

| 목적 | 일상 속 활동·자세 패턴을 감지해 AI 엔진의 루틴 판단(UC11)에 사용할 입력 데이터를 제공한다 |
| 사전 조건 | 홈카메라가 설치되어 있고, 아내가 모션 모니터링 기능 사용에 동의한 상태 (※ MVP 범위 제외, Phase 2 기능) |
| 사후 조건 | 당일 누적된 활동 데이터가 시스템에 전달되어 다음 날 AI 엔진의 루틴 판단(UC11 → UC3)에 반영된다 |

**기본 흐름**
1. [외부 시스템] 홈카메라 시스템이 일상 행동·자세 패턴(장시간 서 있기, 반복 숙이기, 물건 들기, 휴식 부족 등)을 감지한다.
2. [시스템] 감지된 데이터를 '실시간' 탭에서 조회 가능하도록 제공한다.
3. [시스템] 하루 동안의 데이터를 누적한다.
4. [시스템] 다음 날 AI 엔진 판단 요청(UC11) 시 누적 데이터를 함께 전달한다.

**대안 흐름**
- A1. 아내가 실시간 탭에서 당일 활동 로그만 확인하고 별도 조치를 취하지 않아도, 데이터는 익일 AI 엔진 판단에 자동 반영된다.

**예외 흐름**
- E1. 홈카메라 연결이 끊기거나 데이터 전송이 실패하는 경우, [시스템]은 해당 기간 데이터 없음으로 처리하고 AI 엔진은 컨디션 입력값만으로 판단한다.
- E2. 감지 데이터가 의료적 진단으로 오인될 소지를 방지하기 위해, [시스템]은 화면에 "진단 기능 아님" 안내를 항상 표시한다.
- E3. 사용자가 촬영 동의를 철회하는 경우, [시스템]은 즉시 데이터 수집을 중단하고 컨디션 입력 기반 판단 방식으로 전환한다.

**관련 기능 요구사항 후보**: F6-1 (홈카메라 기반 활동 자세 확인, MVP 제외·Phase 2)
